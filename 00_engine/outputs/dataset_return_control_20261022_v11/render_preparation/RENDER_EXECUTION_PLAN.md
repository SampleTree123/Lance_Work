## 脚本结构和参数约定（待实现，不是可运行命令）

1. plan：读取候选、媒体配置、目录和参考清单，生成主任务／参考任务及输出映射。输入包含candidate-root、media-profile、output-root、split、kind、job-ids、limit、shard-index／shard-count；固定任务ID及输入摘要，路径输出为根相对路径／UE Object Path。
2. render：共用任务装配器解析人物、衣服、发型、动作、镜头、场景、曝光，再用MRQ渲染；machine-profile只决定机器路径、资源和并行，不改变内容。Windows／Linux只更换启动适配层。复用现有渲染底层，不直接把旧640节点第一批执行器当作支持v11。
3. encode：PNG序列编码MP4，保留30fps及精确300帧；以临时文件写入后完成检查再发布。
4. resume／report：成功任务按相同输入和配置摘要复用；失败任务记录错误并继续下一独立任务，不无限重试。多个worker独立领取分片，输出目录不冲突；每任务记录实际引擎、配置、文件大小、耗时和错误。

运行中的UE共享操作保持单worker串行。本机先1GPU／1UE进程；服务器先单GPU基准，再按分配GPU数分片。每个GPU独立UE进程，不假定单片自动利用所有GPU；每进程按场景批次复用加载，控制内存累计和临时帧空间。

## 本地验证与迁移顺序

1. 收拢剩余参考制作参数：动作参考载体／背景、人物和发型的统一拍摄布置、服装无人体展示布置；使用已有参考视角与数量规则。
2. 实现任务生成器和参数化共用渲染入口，清理运行依赖中的Windows绝对路径，候选历史路径以映射解析，不重写旧证据。
3. 本地先拍少量当前节点：横／竖、静止／运动镜头、明／暗或复杂场景；身份、发型、服装、场景图和动作参考各包含一个代表。选择来自当前候选和允许组合；不给全部组合增加额外审计。
4. 检查输出尺寸、帧数、完整解码与代表画面，确认衣发跟随／曝光／贴图／参考对齐；实测耗时、显存和体积，记录最终解析的画质参数。测试一次续跑不重复渲染。
5. 本地样片成功后构建上传清单：项目.uproject、Config、所需Plugins／Source及Content（含外部Actor／WorldPartition／CC材质依赖）、执行脚本、候选和配置。Git不承担二进制资产传输。优先完整携带现用项目Content避免漏依赖；不借迁移删除源资产。排除旧媒体、Saved、Intermediate、本地DDC及Windows编译缓存；Linux插件需有对应版本或源码。
6. 服务器确认UE精确版本、Linux插件及实际GPU资源；加载同一项目副本，先运行与本地相同的少量任务，比较构图／材质／曝光／颜色。Windows与Linux不同渲染后端不要求逐像素相等，但不允许未经说明降级项目的光照／反射能力。
7. 服务器小批测出每任务耗时及资源后确定并发和分片，再批量生产；最终媒体按清单汇总。完整编码且确认可用后清理该任务的中间PNG，保留约定的小样原帧。失败任务输入和日志保留，修复后显式重跑。
