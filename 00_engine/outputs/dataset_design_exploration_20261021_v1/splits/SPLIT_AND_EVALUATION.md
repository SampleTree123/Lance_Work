# 数据划分、分支语义与评测候选

日期：2026-10-21。状态：研究建议，未冻结资产 ID、未生成正式划分、未改现行契约，未启动渲染。所有数字是预算候选，不是已验证可采样数量。

本轮默认候选按 **2,500 个训练侧主视频节点 + 500 个测试主视频节点，12,000 个训练侧 session + 3,000 个测试 session** 理解。根视频、中间结果、分支源、分支结果都计入主节点预算；引用同一个节点不重复计视频。**参考影片是否也包含在这 3,000 个视频内，尚待用户决定，不在本分工冻结。**每个 session 有 2–5 次编辑；linear : one historical fork = 2 : 1。单轮只改一个属性，完整继承选中的历史状态，不合并弃支。

## 1. 推荐结论与适用边界

推荐先用候选 A：**未见场景为主测，同分布对照辅助，组合留出仅作探索性诊断**。候选 B 用一部分预算加未见人物，适合最终把用户所说的“未见任务”解释为“未见人物”时切换。用户尚未定义“未见任务”究竟是未见人物、取值、组合还是整类编辑；不能替用户冻结这一表述。整类编辑不进训练的候选 C 只作另一个研究问题，不建议在首批主结果里混用。

训练与测试的完整节点、规范配置哈希、权威视频及其派生帧不得重叠；相同单项资产、相同编辑类别可以重叠。否则，若要求身份、场景、动作、相机、服装等所有取值都 100% 隔离，500 个测试视频会同时承受多个变化，难以判断失败来自哪个变化，还会削弱合法单属性边的连接。已有男女或其他硬兼容域允许分别连通，不能为追求全局连通制造非法边。

本轮已由主任务实读目录核对：40 身份（20 女/20 男）、21 场景/点位、25 动作类别（带性别变体）、21 相机、2 画幅、7 发色、女性 79/男性 73 个服装预设、女性 20/男性 13 个发型条目。本分工另读 `../inventory/normalized_inventory.json` 确认 40/25/21/2/7 子集。**具体可用 ID、服装/发型规则、1,428 条人工排除及最终兼容关系，以主报告的实读 catalog 为准**。以下预留数量必须在这些约束下检查，不能把任意笛卡尔积当可用空间。

现行 V1 是另一批冻结契约：4 个编辑轴、3–5 轮、4,000 条链，不支持本轮分支字段。这里只沿用“完整配置定节点、单属性定边、确定性媒体复用”的原则；2–5 轮与 historical fork 是待设计的新 session 层，不能声称已经由现行 V1 实现。[配置图 V1](../../../../20_planning/data_design/schema/CONFIG_GRAPH_SCHEMA_V1.md)、[采样 V1](../../../../20_planning/data_design/sampling/MULTI_ROUND_CHAIN_SAMPLING_V1.md)、[文本 V1](../../../../20_planning/data_design/schema/MULTI_ROUND_VIDEO_EDIT_TEXT_SCHEMA_V1.md)。

## 2. 四种“未见”分别能得出什么结论

| 划分名称 | 训练中留出的内容 | 能支持的结论 | 不能由此声称 |
| --- | --- | --- | --- |
| 未见场景值 | 整个场景资产族；其地图变体、点位及派生参考也一起留出 | 在新场景中保留人物/动作并执行已学编辑，或按合法参考切入新场景 | 已学会训练从未出现的编辑类别；能泛化到任意真实场景 |
| 未见人物值 | 身份及其所有服装、发型、相机派生外观 | 在新人物上保持身份，或按参考执行换人 | 身份替换这一任务本身未见；底座预训练没见过该人 |
| 未见任务类别 | 某个编辑类别在全部训练边中为零，连等价监督、相应指令与正反向边也不能出现 | 从其他任务迁移到整类新操作的能力，结论取决于底座与条件 | 只把某个跑步动作留出就称“未见动作编辑任务” |
| 未见组合 | 各属性值和各编辑类别分别有训练覆盖，但选定二元组合或编辑程序在训练完全缺席 | 将已知操作/属性组合用于新组合；可分状态组合与程序组合报告 | 全新原子能力；仅换一句指令即构成组合泛化 |

“换背景”在训练出现过，测试换到新森林，是未见场景值；“换动作”训练出现过，测试改成新舞蹈，是未见动作值。只有训练里完全没有换动作类别，测试才叫未见任务类别。

组合建议优先限定 **一个可审计的二元组合规则**，例如某组已见身份 × 已见场景的配对只在测试出现。训练必须分别出现这些身份、场景及相同编辑类别。补充的程序组合可以留出“从较早历史分叉后再改动作”这类结构，但需确保训练仍有分叉、有动作编辑；若训练没有任何分叉，就应单列为未见交互结构。组合留出涉及的目标/历史/reference 也必须遵守规则；只在当前目标节点禁用、却在训练参考中出现，不算严格组合留出。

这些是本项目的操作定义。CoGenT 用已知属性的新组合测试组合泛化，SCAN 区分不同组合划分的泛化难度，支持我们把“新值”“新组合”“新操作类别”分开报告；它们并不证明本项目的某个配额最优。[CLEVR/CoGenT](https://cs.stanford.edu/people/jcjohns/clevr/)、[SCAN，ICML 2018](https://proceedings.mlr.press/v80/lake18a.html)。

## 3. 500 个测试视频的候选分层

下表是**预算分区**，不是要求每个视频都带该分层的未见标签。每个分区自带根、中间结果和必要连接节点，不从训练池借媒体。场景分区中，允许有测试专用的已见场景节点，用来连接到未见场景；这些连接节点本身不标“未见场景”。session 的主层由预先冻结的评测目标决定，另保存所有实际标签。

| 候选 | 同分布对照 | 未见场景 | 未见组合 | 未见人物/类别 | 合计 |
| --- | ---: | ---: | ---: | ---: | ---: |
| A，推荐：唯一视频 / session | 80 / 480 | 340 / 2,040 | 80 / 480 | 0 | 500 / 3,000 |
| B，加人物诊断：唯一视频 / session | 80 / 480 | 220 / 1,320 | 100 / 600 | 人物 100 / 600 | 500 / 3,000 |
| C，另题研究：唯一视频 / session | 80 / 480 | 220 / 1,320 | 100 / 600 | 类别 100 / 600 | 500 / 3,000 |

A 把 68% 测试节点留给场景主测，组合层只看可行性和失败模式。拆成 3 小池后，80 个对照/组合节点还要各自容纳根、连接点和两个兼容域；每池实际独立 family 与合法唯一 session 数可能很少，反复游走出的数百条 session 不能弥补独立资产族不足。若 80 节点组合池达不到 480 个合法唯一 session，或严重依赖重复边，就把这部分预算并回场景池，组合仅作标签分析，不宣称严格组合泛化已经充分验证。该回退须在看模型结果前通过结构检查决定，并重写冻结 manifest。B 能加人物泛化，但四池更薄，不应据此声称所有轴都稳健。C 要从训练删掉整个类别，并重新平衡边、指令和组合规则；不同候选的训练分布不同，不能把跨候选结果当单个模型的控制变量比较。

场景预留的起始参数可设为 21 个场景族中测试 4、开发验证 1，其余 16 用于开发训练；最终训练侧可覆盖 17 个。这里的“族”须按共享底图/资产关系识别；若 21 张图并非 21 个独立族，数量须相应减少。B 可设测试人物 8（女 4/男 4）、开发验证人物 4（女 2/男 2），最终训练人物 32。A 不强留人物，40 个身份允许在两侧以不同完整配置出现。人物留出会缩小可换人的同域池，须先验可采样性。

每层保持相近的长度、linear/fork、编辑轴分布、横竖比例和兼容域比例；主测分别报告各层及 matched 对照差值。场景层再区分：初始就处于新场景、把已见场景换到新场景、在新场景中编辑其他属性。不要把新场景层中的所有回合都当成“换场景”任务。

不要先生成 15,000 条 session 再逐行随机切分。先冻结资产族留出与组合规则，再从合法原子边出发长出分属各池的小图、根和 session；每个新端点先按规范化配置去重。每层预留连接节点预算，达到唯一视频上限后只在已登记端点间增加合法边或采 session，不偷偷添加第 501 个测试视频。若层内无法达到 session 唯一路径数，明确回报缺口，调整候选，不用文本改写充数。

## 4. 验证集从哪里来

500 个测试视频和 3,000 个测试 session 只用于最终评测，不调参数、不挑 checkpoint、不据此选划分或反复换指令。开发验证从 2,500 个训练侧视频预算内部产生：起始可预留 250 节点、1,200 session，剩余 2,250 节点、10,800 session 用于开发训练。该 250/1,200 是配额目标，要按独立 family 实现，不能为凑整数拆开同一 family。

开发验证里同时有已见资产对照与代理分布外验证，代理场景/身份不得与最终测试的留出族相同。组合验证使用另一组二元组合或程序实例，最终测试组合仍封存。分层和代理留出在看模型结果之前确定，避免只挑“掉分最大”的场景。

最终若必须保留“2,500 视频、12,000 session 全用于 fit”的说法，可以在开发协议选定、所有选择冻结后，用完整训练侧重新训练一次；明确记录这是 **final refit**，此时原开发验证不再是该最终模型的独立验证集。若不做 refit，则诚实报告 2,250/10,800 fit + 250/1,200 validation，不能仍称 12,000 都用于训练。两条路径均不占用测试集。WILDS 明确禁止用测试集训练或选模型；其标准提交还要求训练与验证保持分离。本候选 refit 选项是本项目可选协议，并非 WILDS 标准协议。[WILDS 提交规则](https://wilds.stanford.edu/submit/)。

## 5. 参考图/参考视频条件下的 seen 与 unseen

“未见”必须带范围：默认指本项目训练侧（含训练 reference、视频抽帧、增强和检索库）未出现；不保证底座预训练未见。记录 `unseen_scope=dataset_training`，无法审计底座时写 unknown。

测试时给出未见人物/衣服/动作/场景的参考，是任务输入，可以合法。此时结论是 **参考条件下迁移到训练未见资产**。参考可来自预先固定的身份照、服装图或动作示范，且标明图/视频、可见属性、是否同视角同动作。文本模式、图参考模式、视频参考模式分别比较，不能把多看了参考的视频模型与纯文本模型合成一个主表数值。

参考不能直接取待预测 target 视频、其目标帧、或同完整状态的可复制衍生物。仅用于人物身份的参考，也不应同时提供目标的全部动作、场景和相机；否则任务可能退化为复述参考，须另列为 reconstruction / copy 诊断，不能作为编辑泛化主结果。记录 reference 与 target 的身份、场景、动作、相机重叠掩码和派生来源；与当前 source 同内容的输入视频是合法编辑输入，不等于未来 target 泄漏。

参考视频必须单独列账，不能隐含为零成本；历史节点的视频引用已包含在主节点计数中。默认候选把 2,500/500 作为主视频池，若另渲唯一参考影片，总渲染视频数 = 3,000 + 未与主媒体重合的唯一参考影片数。**若用户要求 3,000 是全部渲染视频的硬总额，则必须先为参考影片扣减主节点预算，再重跑分层和图容量检查。**两种口径暂并列，不能把“主视频数 3,000”写成“总渲染数 3,000 已锁定”。外部静态参考图片单独计数和存储；其授权和 provenance 由主报告负责。测试 reference 不进入训练检索索引、模板自动生成示例或评测器调试集。

## 6. 分支究竟继承哪一版

必须同时保存 **节点**与**出现记录 occurrence**。节点描述一段确定视频；同一节点可在回退后再出现。occurrence 描述它在某个 session 何时出现、由哪一次编辑得到。

对第 t 次编辑保存 `parent_occurrence_id`，其所指节点才是本轮原子边的 source；默认 linear 指上一次出现，fork 指更早出现。令源状态为 C(parent)，则 C(target) = replace_one_axis(C(parent), axis, value)。弃支上的相机、衣服、动作均不会自动留下来。相对于“时间线上最后一版”，新结果可能差两个以上属性，这不违反原子性；原子性永远相对被选中的 source 检查。

例如根为“红衣、走路、近景”，先换蓝衣，再拉远；现在要求“从换蓝衣后的版本继续，改为跑步”。结果必须是“蓝衣、跑步、近景”。得到“蓝衣、跑步、远景”是混入弃支相机；把结果相对最后一版检查，会误判合法结果是多属性编辑。

一次 fork 后继续编辑，从 fork 的新结果向前走；one historical fork 整个 session 只能出现一次非最新 source 选择。历史分叉可以发生在根或中间版本；根只是候选源之一。旧分支保留在可见历史中供理解，但不合并进新状态。

若多次访问同一个节点，`parent_occurrence_id` 仍记录用户语义所指的那次出现；针对相同视频/完整状态，可另存 `acceptable_source_occurrence_ids`。报告严格 occurrence 命中率与等价节点命中率；“最初那版”应严格指根，含糊的“红衣近景那版”可接受真正等价的重复出现。衣服一样、但相机或时间窗口不同，不能因一个属性相同就视为完整继承等价。若用户明确指定某次出现，状态等价也不能抹去指代错误；两种分数分别报告。

## 7. source 选择、生成与 rollout 分开评测

| 协议 | 模型合法输入 | 回答的问题 | 不能混称 |
| --- | --- | --- | --- |
| known-reference 单轮 | 任务原本就给出的源视频、当前指令、约定目标参考 | 已知源输入时的编辑质量 | 不能称模型从历史自主选源 |
| oracle-source 诊断 | 评测器用 hidden GT 选对历史源，再喂给模型 | 排除选源错误后，编辑器能否工作 | 不能作为自主分支主结果 |
| 自主选源、GT 历史诊断 | 可见完整历史与当前指令；模型选源，历史媒体来自 GT | 在无先前画面误差时能否识别正确版本 | 不能称端到端 rollout |
| 自主选源 + rollout，主结果 | 从根开始，只用已生成历史、可见指令及合法参考；模型自行判断 history source | 全 session 表现及错误传播 | 不能把中间 GT 悄悄灌回历史 |

GT source 标签供训练监督/评测使用，并不等于推理时必须把标签喂模型；架构如何选源由其他对话负责。所有方法必须共享相同的可见历史、reference 和槽位编号协议。用户自己提供“第 1 次编辑后的版本”这样的编号是合法指令；评测器额外注入 `parent_occurrence_id` 则是 oracle。

多模态历史应至少约定：每轮用户文本、生成后可见的视频或其约定帧采样、公开 reference；是否还显示弃支视频/缩略图、显示全部还是截断、采样多少帧须冻结。需要视觉辨别的“戴帽子的那版”若只给文本而视觉证据被隐藏，应标输入不充分或排除该语言形式；不能用 evaluator 读 hidden GT 来补全模型看不到的线索。视频历史与单帧历史是不同输入条件，单列报告。

public model view 不含节点配置、资产内部 ID、规范哈希、未来 target URI、正确 parent 标签、未来指令或 evaluator 判定。用不暗示答案的公开 occurrence 槽位与媒体句柄映射历史；hidden GT 置于独立视图。oracle 诊断显式开关并单列输出。GT-only 的 branch_examples 不是可以原样喂模型的 prompt。

rollout 需对齐当前选中的**已生成**历史源，不能总用最新一版，也不能在回退时恢复 GT 视频。主分数按 hidden target 状态判编辑成功与保持不变；同时保留 oracle-source 与 GT-history 诊断。三者差距提示选源/历史误差的影响，但不是严格因果分解，因为后续错误会改变输入分布。

## 8. 长度、分支位置与报告

主报告图候选的长度配额为：linear 在 2/3/4/5 各 25%；fork 只用 3/4/5，比例 20%/40%/40%。训练 linear 各长度 2,000，fork 为 800/1,600/1,600，合计长度 2/3/4/5 为 2,000/2,800/3,600/3,600；测试 linear 各长度 500，fork 为 200/400/400，合计为 500/700/900/900。训练合计 44,800 次编辑、测试 11,200 次编辑。

本分工另提供 **uniform-length alternative**：session 2/3/4/5 各 25%，训练侧各 3,000、测试各 750；每种长度 linear : fork = 2 : 1。训练每长度 2,000 linear + 1,000 fork，测试每长度 500 + 250。总计训练 8,000/4,000、测试 2,000/1,000；训练 42,000 次编辑、测试 10,500 次编辑。该方案包含 L=2 的根分叉；主报告图候选不含。两套配额不能混用，最终由主报告统一选择，不在这里冻结。回合计数均是重复引用次数，不是独立视频数。

fork round 从 2 到 L；第 t 轮可选 occurrence 0 到 t−2，避免把最新源标 fork。L=2 只有第 2 轮从根分叉。对 L≥3，先均衡分支轮次，再在可用历史中均衡近/远源；另报告根源与中间源。不能强制短链填满不存在的“早/中/晚 × 根/中间”组合。仅在 uniform alternative 中，L=3/4/5 的测试 fork 数均为 250，可分别按 125/125、84/83/83、63/63/62/62 分到各合法轮次；训练各 1,000 则可按 500/500、334/333/333、250/250/250/250。主图方案必须用自己的 200/400/400 等 fork 配额重新分配轮次，不能复制这一数字。各层只需近似保持比例，不为凑各交叉格制造重复 session。

主报告至少包含：分层的当前属性编辑成功、非目标属性保持、身份保持、时间稳定性；严格选源/等价选源；最终回合与全 session 成功率；按轮次、fork 前/当轮/之后的性能。自动评分不能读取 GT 元数据后直接把配置差异当模型生成正确性；GT 配置是答案标签，模型视频是否实现该答案需由固定的视觉评测或人工盲评判定。视频质量应拆维度，VBench 提供身份一致性、运动和闪烁等分维度思路，但它不是本项目的编辑正确性 oracle。[VBench 项目](https://vchitect.github.io/VBench-project/)。

复用端点和边是节省渲染的机制，也意味着 3,000 条测试 session 并非 3,000 个独立世界。每个 manifest 报告唯一节点/有向边/session/family 数、边与节点复用次数、完整路径重复数，以及有效场景/人物族数。语言改写、同一路径的不同语言、同根分支及其子路径归于同一 provenance family；换词不增加 family 数。不同的编辑顺序是不同 session，但若共享根/生成谱系仍归同 family。

先在 family 内平均，再以 family 为单位报告均值和置信区间；不要按 turn 独立 bootstrap。若不同 family 仍共享节点/边，按共享媒体连通的依赖组 bootstrap；若形成巨型依赖组，明确无法给出可靠的独立样本区间，并补报场景/身份族聚合或留一族诊断。不要为了图连通把所有节点宣称一个“独立 family”，也不要任意给共享路径换 family ID。只有 4 个未见场景族时，每族结果与族均值比窄误差条更有解释力。主表同时给 session 等权分数，显示高复用 family 是否改变结论。

## 9. 冻结前仅需的门禁

1. 资产族留出、目标条件、组合规则与人工排除相容；每个 session 的全部端点/参考/历史落在所属媒体池。
2. train/dev/test 规范配置哈希、节点媒体和派生物零重叠；参考目标泄漏为零；完整有序编辑树与语言变体跨划分重叠为零。
3. 每条边相对 parent 恰好改一个允许轴；每个 fork 指向此前非最新 occurrence；继承完整源状态；每个 fork session 精确一次 fork。
4. 主视频预算包括根和中间结果；reference 视频单列并按用户选择的预算口径计算总渲染成本；session 不靠改写去重；逐池统计合法边数、可行唯一 session 数和复用。
5. 先冻结 public/hidden 输入视图、验证选型协议与测试封存方式，再跑模型；分层数字只是候选，通过以上可行性检查后才能成为生产 manifest。

本目录配套 `split_candidates.json` 为参数化候选，`branch_examples.json` 为少量正反例；自验仅验证这些例子的继承、原子性与信息边界，不代表正式图、媒体或采样器已通过。
