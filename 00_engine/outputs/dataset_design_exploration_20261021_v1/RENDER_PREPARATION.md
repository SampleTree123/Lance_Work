# 主视频与参考素材：渲染准备

2026-10-21。离线规划；本轮未操作UE，未生成正式渲染作业。

## 1. 先采用的工作方式

推荐分成三份清单：**视频节点清单、编辑会话清单、参考素材清单**。先在JSON里生成、比较和调整，再渲染最终去重的视频节点与参考需求。文本改写和会话重新采样通常不需要补渲视频。

主视频是编辑历史里的源／中间／最终结果。参考素材是用户为了说明“改成什么”而提供的图或视频，两者角色不同。当前预算建议解释为3000个主视频，参考单独计数；如果3000是所有视频文件的硬上限，就必须先扣除动作／无人背景参考视频，再重新分配主节点，不能先承诺两者都包含。

## 2. 已核对的输入

实际目录快照在[inventory/summary.json](./inventory/summary.json)，完整服装／头发选择在[inventory/appearance_catalog.json](./inventory/appearance_catalog.json)。

- 40个人物：20女、20男；25种动作、50个性别变体；21镜头；横竖两个画幅。
- 21个当前选定场景点，以10月21日检查点为准。面板目录另保留历史候选，不应把53条历史点位全部当成本次用户选定点。
- 7发色；女性20、男性13条发型记录，跨性别按发型ID合并是28种，按性别适配仍为33项。
- 女性79、男性73套预设。预设引用的衣物registry ID为129／158，加实际引用的共享鞋9／22，共318个候选ID；包含捆绑件、材质变体和兼容限制，不能直接称318件可独立编辑衣物。
- 保留当前点位排除组合。允许的场景／动作／镜头组合只是当前选择范围，不能把排除组合重新加入生成。

有一个已处理的读取陷阱：旧静态面板catalog仍包含过期动作。此次规范化清单使用生产动作库并移除已退出的“四周张望”，而不是从旧静态列表读取全部动作。

## 3. 继承原分支的渲染接入

准确依据为[原分支交接](../render_readiness_20261021_v1/HANDOFF.md)：

- 从用户已保存的源关卡制作新的渲染副本，使用正式槽位流程。
- 镜头继承关卡后期处理体积的曝光，清除旧镜头曝光覆盖。不再把点位里的旧曝光补偿写回。
- 共用预热为120个引擎预热帧、32个渲染预热采样；不更改输出首帧、帧数和动作范围。
- 本机审查纹理预算7000MB，MRQ临时10240MB，正常完成恢复。其他显卡重新确定本机配置。
- 已完成的是3帧静态样片和相关接入检查；不能用它估算完整动作的每帧耗时，也不能当全人物动态成片验收。

正式清单应记录源关卡／点位快照、角色和外观版本、完整相机轨迹、动作时间映射、表情时钟、画幅、帧率、分辨率、渲染配置。切换场景顺序是执行调度，不改变节点语义。

## 4. 时长与镜头，先沿用已有能力

现有生产动作库已经有10秒归一化时间规则：包括原速截取、减速、首尾停留和重复拼接。今晚只核对规则，不把库中的历史“待烘焙”状态当成当前所有资产已经或尚未完成的结论。

建议第一轮规格讨论优先考虑**10秒、30帧、1280×720横屏**：它与现有10秒动作合同及720p审查轨迹比较接近，减少重新定时的工作。这是执行便利的候选，不是已证明对训练最优。若模型训练预算需要5秒／24帧，应统一重新定义动作窗口和镜头时间，不能简单截掉后半段，导致挥手、转身、环绕等编辑含义缺失。

画幅暂作为同一图族的固定条件，比把横竖切换当一种编辑更直观。是否两种画幅都生产，可在最终分配节点时决定。

场景边保持相同的镜头策略和身体动作，允许不同场景使用其已保存的位置、地面高度和环境光照。镜头实际世界坐标随点位映射属于派生配置，不应误判为额外镜头编辑。动作边保留相机策略，但若使用动作跟随镜头，最终相机轨迹也可能由动作派生；需要明确语义，不能声称像素级镜头轨迹完全相同。

## 5. 参考库如何控制规模

详细方案见[REFERENCE_DESIGN.md](./references/REFERENCE_DESIGN.md)。推荐首先准备能被最终采样边实际用到的内容：

| 编辑 | 首选参考 | 去重依据 |
| --- | --- | --- |
| 发色 | 色名；需要时补规范色卡 | 颜色定义，不按每人物重复 |
| 发型 | 其他人物承载的正面照，必要时背面照 | 发型、性别适配、承载人物、视角、固定发色及拍摄配置 |
| 人物身份 | 中性光正面照；身份范围先定义 | 身份版本、视角、拍摄配置 |
| 单件衣服 | 四视角图库，单次指令取必要的1–2张 | 衣件与材质、穿着适配、承载人物、视角 |
| 动作 | 不同人物、固定服装的动作短片 | 动作、骨架适配、时序、镜头轨迹、画幅、承载配置 |
| 背景 | 无人物背景图；运动镜头用无人短片 | 场景点、实际镜头轨迹、时序、画幅、环境版本 |
| 镜头 | 文字 | 不增加参考媒体 |

特别注意：`front_full`只是镜头策略名称，跟随移动角色时未必静止。无人背景若仍需要原动作决定的跟随轨迹，应在去掉人物前固定那条轨迹；只按“场景+正面全身”合并会合错。动作参考与目标独立渲染，但允许按公开请求匹配机位、时长与节奏。

无需一开始渲28发型×40人物、318衣物×40人物、25动作×21镜头×21场景。参考承载人物和中性背景独立选定，然后从实际边收集去重需求。衣物不能独立换、画面完全看不到的衣物，不产生该边；暂时被遮住的配置仍留在节点内，供后续镜头或历史回退继承。

## 6. 成本：目前能算什么

[render_budget_scenarios.json](./render_budget_scenarios.json)由[prepare_render_budget.py](./prepare_render_budget.py)生成，共12种候选。时间和码率栏是代入假设，尚无真实批量基准。

以3000个主视频、10秒、30帧为例：

- 900,000个输出帧。
- 若成品平均码率为8／16／32Mbps，主视频约30／60／120GB（十进制GB），不含参考、缓存和临时帧。
- 若每帧实测0.1／0.5／1秒，单GPU纯出帧约25／125／250小时；加载、预热、装配、编码、失败重试另算。
- 720p未压缩RGB8约2.49TB；1080p约5.60TB。PNG压缩和EXR不能直接用这个数字代替实际存储。
- 若每主节点单独预热，共360,000个引擎预热帧和96,000个渲染预热采样。两者不是同一种输出帧，不能直接相加按每帧价格计算。

总视频数为主视频与参考视频渲染键的并集大小；总耗时按每作业“加载／装配+预热+出帧+编码”累计。最有效的调度优化是按关卡和兼容资产分组批量渲节点，同时保持每节点的确定性初始化。

## 7. 明早确认后如何快速落地

1. 确定预算是否仅主视频、目标编辑轴、测试环境和视频规格。
2. 以混合图候选生成正式节点／边／会话清单，同时派生参考需求；先检查数量与几个代表分叉。
3. 先渲一小组完整可训练样例：包含一条直链、一条分叉及其参考，不仅看孤立美观视频。建议总量约20–40主节点，具体由实际共享端点决定。
4. 一次检查三个现实问题：编辑目标可辨、未编辑属性保持、模型实际输入的参考足够说明要求。发现某种条件表达不清就改该类，不重审全部资产。
5. 小组通过后按同一节点键继续批量生产。训练派生编码与原始成片分开记录，后续改会话文本和结构尽量不触发重渲。

本轮不提交正式作业。下一步直接利用这些清单和样例讨论，不重新启动资产审查。
