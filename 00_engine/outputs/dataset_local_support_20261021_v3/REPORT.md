# 第三版试构建：已经做到什么，还差什么

这次已经在原来的视频预算内生成足量编辑链，所有节点都实际用到了。**它是一份可继续讨论的完整候选，但测试集重复仍然偏多，暂不直接作为最终渲染清单。**

| 项目 | 训练集 | 测试集 |
| --- | ---: | ---: |
| 不同的视频配置 | 2,500 | 500 |
| 不同结构的编辑链 | 12,000 | 2,400 |
| 没有被链使用的视频配置 | 0 | 0 |
| 人物身份 | 40 | 40 |
| 服装来源组 / 合法搭配组 | 37 / 45 | 37 / 45 |
| 场景点位 | 21 | 21 |

两部分也都覆盖28款独立发型、7种发色、25个动作和21种镜头。这是类别覆盖，不代表每件服装变体、每种搭配或每种编辑方向都已覆盖。当前只有配置和关系，没有生成视频。

## 这次怎么做

同一组视频允许“先换发型再换衣服”和“先换衣服再换发型”等路径共用节点。不同人物分配不同的局部候选，身份替换与其他编辑之间补上连接，避免某个人物只剩身份替换可做。随后在原预算内补齐遗漏的服装搭配组和点位。

链的起点平衡人物；编辑类别和服装模式根据累计使用次数作平衡。这个实现允许局部候选有限，没有宣称每个视频仍能等概率编辑到完整资产库。没有禁止自然回访、单属性整链或末轮分叉，也没有过滤那些用最新版本也可能得到相同结果的分叉。

## 比上一版改善了什么

训练链中，发生过回到历史视频的比例从约70%降到48.3%。所有3,000个节点都有实际用途；单件/整套服装在两者正式均可选的情况下接近一半一半。身份、衣物和场景等仍按正式合法规则改变。

独立检查确认：每条边只改变一个语义属性；分叉完整继承被选择的历史版本；训练测试完整视频状态没有重合；链长、直链/分叉比例以及唯一结构数量符合原计划。这些是配置层检查，尚无视觉或训练效果验证。

## 还需要看清的取舍

测试链中仍有67.0%曾回到历史视频，和旧代表接近。这个数字不表示重复链；链的完整路径互不相同，但会用回链内之前的视频。若按每次编辑计，训练18.0%、测试29.1%回到已有历史节点。测试中约14%的链从头到尾只在同一对视频间修改，这是当前最值得继续讨论的问题。

分叉选择历史版本后，未被本次编辑修改的内容确实与最新版本不同的比例，训练为63.5%、测试为47.2%。其余并非结构错误，但对检验历史选择能力的信息较少。自然等价分叉仍按用户决定允许。

此外，部分发型、动作、镜头和场景的具体转换方向比v1少；不是所有多样性指标都改善。当前链主要组合两到三个编辑属性，测试单属性整链约24.8%。因此本次可以确认“预算内构造和配置正确性跑通”，不能直接宣布“整体多样性足够”。

## 后续准备

已按这份实际候选重新列出参考需求：**1,025张图片、251段动作参考视频**，另计于3,000个主视频。所有媒体路径仍为空。参考需求会随最终节点/边变化，动作载体、分辨率、帧率、时长、画幅还没有冻结。

下一步建议先讨论测试集的重复程度是否需要进一步降低，再决定是否采用这份候选。没有扩大视频预算，也没有启动UE或渲染。
