# 第二轮：参考素材会改变任务，先比较条件含义再算数量

日期：2026-10-21。状态：离线研究与可执行规划，未渲染、未运行编辑模型、未改第一轮文件。输入来自第一轮最终main图，SHA256保存在 [analysis_results.json](./analysis_results.json)。当前图仍是六字段、五可变轴，服装/发型形状固定；本文不把这部分需求写成完整多模态数据预算。identity究竟只指脸还是包含体型仍不在本子任务冻结；头部proxy仅检查面部证据，不能据此替用户定义完整identity轴。

## 1. 本轮最值得改变的结论

建议把“参考越贴近GT越好”改为两条并存路线：一条给严格匹配的场景与动作条件，评价可控重建；另一条给独立人物和机位的示范，评价从示范提取指定属性、保留选中历史版本。两条的可接受输出不同，不能只换参考图而沿用同一套逐像素评分。

本轮也修正第一轮过宽的“GT派生参考一律拒绝”：Kiwi-Edit/RefVIE公开从目标首帧提取编辑区域、去掉前景形成背景参考；RCEdit也采用目标驱动的参考补全，同时检查参考和目标近重复。它是有一手先例的数据构建路线。对本项目，应记录来源并与asset-first独立参考分轨，实验测量复制捷径，而不能直接定性为无效数据。[Kiwi-Edit §3.1](https://arxiv.org/html/2603.02175v1)、[RCEdit §3.2/B.2](https://carpedkm.github.io/RCEdit-500K/RCEdit_paper_lowres.pdf)

但“给了参考”和“用到了历史”是两种能力。精确背景参考可能暗示机位和跟拍动作，帮助绕过文字中的source指代；它仍无法单独给出应该保留的脸和发色。关键控制是：**相同历史、相同强参考，只改变从哪个历史版本继续，正确结果必须不同。**本轮已找到无需新增GT节点的候选对，并做出小型输入manifest。

| 参考视角分组 | 一个独立中性carrier的动作clip | 两个sex-fit carrier的动作clip | 按场景+分组给规范照片 | 同轨迹无人背景clip |
| --- | ---: | ---: | ---: | ---: |
| 1个规范正面 | 25 | 50 | 21 | 845 |
| 2组（后/非后） | 50 | 99 | 41 | 845 |
| 4组（前/侧/后/高低） | 96 | 178 | 75 | 845 |

这里的2/4/8组是提前声明的语义聚类，**不是已验证的几何覆盖或最佳视角选择**。例如8组单列orbit、dolly和头部景别；不能把这组数字写成相机方位精确量化。场景规范照数量少于“21×组数”，是因为只对实际出现的请求组合计数。

为什么单carrier的matched数358不等于487？本情景去掉性别适配维度并共用中性示范；这要求动作可在不同体型间按语义迁移，不能再要求它复现目标身体的每一条屏幕轨迹。双sex-fit也只是匹配粗粒度适配域，不等于逐个identity的身形都匹配。

### 2.1 五条实际可讨论的路线

| 路线 | 当前真实边投影的参考库 | 它真正定义的任务 | 代价或限制 |
| --- | --- | --- | --- |
| C1：完全canonical语义参考 | 25动作clip+21场景照+40人物照 | 跨carrier/机位模仿动作，按场景参考生成环境 | 最便宜，但单张场景照不能唯一规定运动镜头的新露区域；需语义/多解评价 |
| C2：双sex-fit canonical | 50动作clip+21场景照+40人物照 | 同上，降低身体适配跨度 | 仍非精确时序与场景重建；并无模型成功率证据 |
| H1：canonical动作+精确环境轨迹 | 50动作clip+845背景clip+40人物照 | 场景严格，动作语义模仿 | 共895个额外clip，较matched的1,332少437；背景仍占主要预算 |
| H4：四视角组动作+精确环境轨迹 | 178动作clip+845背景clip+40人物照 | 减小示范视角跨度，环境严格 | 共1,023个额外clip；4组如何选图需实测 |
| M：原机位动作+精确环境轨迹 | 487动作clip+845背景clip+40人物照 | 条件高度对齐的受控编辑/合成 | 共1,332个额外clip；不能等同任意真实示例泛化 |

额外参考不并入3,000主节点视频。原matched参考中845/1,332=63.4%的clip来自背景；单独压缩动作参考不能消除场景轨迹成本。H1只是在动作语义任务可接受的前提下节约32.8%，不是质量不变的压缩率。

Reenact Anything将单个视频的语义动作迁移到不同目标图，明确不要求空间对齐；这支持把canonical动作当独立任务研究，但不证明我们的25个UE动作已能跨人、跨机位成功迁移。[作者页面及原摘要](https://studios.disneyresearch.com/2025/07/16/reenact-anything-semantic-video-motion-transfer-using-motion-textual-inversion/)

### 2.2 semantic motion和timing-aligned不能只差一个字段

- semantic：参考说明“做什么动作”，保留源机位和人物；阶段顺序、速度容差、动作完成度由任务规定，不能直接按GT逐帧误差判错。
- timing-aligned：参考还规定起始相位、速度、持续时间或关键阶段时刻。真实GT若没有相应时间窗，不能凭生成reference补出监督。
- motion/camera同时对齐：还携带屏幕布局与相机轨迹；这是更强条件，应单列结果。

第一轮graph没有time-window/rate字段。本轮T=1/2/4/8的曲线表示“每个已出现参考key覆盖T档时序情景”的条件性计划，不是从图里测出的真实T档需求。双carrier下，canonical动作随T为50/100/200/400个clip；4视角为178/356/712/1,424；matched为487/974/1,948/3,896。

完整预算应写为 `487×T_action + 845×T_background`，再加人物照；不能只把动作乘4却默认所有背景轨迹仍与新时序完全一致。如果T意味着新增目标动作窗，也必须新建对应GT节点，不能继续宣称只有原3,000主节点。本轮没有这么做。

production10几何sidecar确有10s、30fps、300帧clock，本轮仅用它作成本情景：matched参考1,332×300=399,600帧；H1为268,500帧。未测每帧渲染秒数、媒体码率和参考实际必要片长，不报告虚构GPU小时或存储收益。

## 3. 精确背景plate为什么强，也为什么一张图未必够

精确plate给出目标场景的纹理、透视和光照；这可以合理降低“生成一个新场景”的难度，使评价更聚焦前景保留和融合。它不必然是坏条件。

但如果正式相机随人物骨盆平移，front_full也不是物理静止相机。一张无人照不包含后续视点的新露区域。此时有三个不同选择：

1. 精确无人背景clip：保留当前GT重建任务；需求键至少包含site、camera、motion/trajectory、aspect、timing及scene-owned曝光规则。
2. 一张/几张背景示例：任务改为参考引导的环境迁移，接受新露区域的合理补全，不能强求它复原唯一UE场景轨迹像素。
3. 限定真正静止或近似静止的镜头子集：只在轨迹位移/视差容忍阈值通过时，用单图近似。不能按preset名字判断。

root已完成正式轨迹离线分析，[camera_summary.json](../observability/camera_summary.json)包含25动作×21镜头×2画幅的1,050条轨迹；按≤1cm位移、≤0.1°视向、≤0.01°FOV范围的近似静止标准，静止数为0。front_full视向可固定，但位移中位14.58cm、最大450.20cm；不能按front名称使用单静帧重建整段。

本目录已继续实际对接它：[trajectory_reference_budget.json](./trajectory_reference_budget.json)。第一轮2,159条used site边全部匹配formal planning轨迹；845个motion/sex/camera/site键可在“不同sex/identity共用同一数值轨迹”的条件下按site+trajectory hash压到808个，最多少37个。这个假设尚未覆盖运行时地面跟随与body-fit适配；不能把808提前写成生产预算。sex不应机械成为背景必需维度，最终应以已解析的真实轨迹去重。

## 4. 实验二：参考能否旁路source指代

对每个真实分支请求，将所有已经展示过的版本当候选source，按“当前编辑轴之外的保留状态”去重。接着模拟reference元数据最多透露哪些源属性：

| test请求 | 分支请求数 | 只含目标轴的reference，可唯一定位保留状态 | reference透露camera/aspect | 再允许动作轨迹/sex fingerprint |
| --- | ---: | ---: | ---: | ---: |
| 动作边 | 219 | 0 | 66（30.1%） | 66（30.1%） |
| 场景边 | 193 | 0 | 19（9.8%） | 97（50.3%） |
| 身份边 | 272 | 0 | 0 | 0 |

这不是模型实验。它假设视觉输入中的线索可以被完全解码，给出**reference帮助选择source的潜在上界**。比如无人背景的动态轨迹可能指纹化某个旧动作，但真实视频能否识别这个指纹还未测试。它也不表示模型只看reference就能生成：脸、发色和其他保留状态仍要来自历史媒体。

因此“多轮得分高”可能混合三件事：遵循reference；选择文字所指历史版本；保持该版本的非编辑内容。建议分开记录目标轴成功、保留轴成功、source指代成功，并测reference-only条件或强/弱文本条件；不把同机位参考带来的source提示能力全记给history理解。

本项目无需先发明新模型来测它。将相同强reference用于两条source-pointer不同的请求：若模型总输出相同结果，就没有按指令保留不同旧版本；若删除reference后目标轴不受影响，则可能文字已完全说明目标，不能声称模型使用了reference。

只看已含图/视频参考的identity/action/site三轴；这些是对现有session的候选重写，不是现成自然语言标注，也不是全部可直接用的训练条目。

| --- | ---: | ---: | --- |
| 复用之前引入的reference | 417 / 416 | 137 / 137 | 原reference可复用；需补稳定标签 |
| 复活弃支reference | 378 / 377 | 126 / 126 | 保留弃支reference即可，不新增GT |
| 纠正先前reference选择 | 6,091 / 4,812 | 1,547 / 1,187 | 把“之前A不用，改B”写清楚；不等于系统先前输出错误 |
| 从历史视频只复制一个轴 | 854 / 840 | 310 / 303 | 把已展示历史视频兼作参考；易误带衣服/身份等其他属性 |

计数可重叠，不能相加当独立样本数。当前图固定服装/发型形状，不能据此生成“只复制衣服却保留头发”的已验证样本。

建议优先做“选择性复制”和“弃支reference复活”。后者明确测试完整历史是否保存了已放弃选择，而不只是当前链的状态。纠正任务要区分用户改主意和模型错误修复：当前挖掘只证明两次合法目标选择存在，没有错误模型输出，不可写成错误修复数据。

### 5.2 已继续做出的12对小型可执行manifest

818条分支请求可找到另一条已展示source，使用同一强reference时仍有合法但不同的目标节点。按无序目标端点对去重后为536对：train身份192/动作141/场景100；test身份46/动作41/场景16。均不需要新增GT节点。JSON仅保存每组最多8个示例，所有图/视频路径均null。

下一步已经实际做了：在test按三个轴各取4对，共12对、24条请求，写入 [input_control_suite.json](./input_control_suite.json)。它们引用20个已规划目标节点、10个主reference key。通过 [build_input_control_suite.py](./build_input_control_suite.py)可复现。

每条请求含显式版本V0/V1等标签、主reference R1、同轴错误候选R2，指令说仅采用R1。每对只改变“从哪个旧版本继续”，其余历史与reference不变；正确目标随之切换。三个可评分控制为：原顺序；R1/R2换顺序但标签固定；去掉明确无关的R2。未来合计72次模型调用，不新增GT视频。另24次“去掉必需历史source”的输入缺失诊断必须单列，不能拿同一GT当公平输入评分。

这些JSON尚不是已经能喂给模型的媒体包：未制作独立carrier参考、未检查脸/发色是否可见、未加入完整自然语言的旧轮指令。当前版本测显式历史版本选择和reference角色绑定；更自然的“回到刚才换人前”需要补充历史文字，不能把显式编号测试冒充隐含意图推理。

### 5.3 建议的子任务规则

| 子任务 | 指令示例 | 允许带入什么 | 必须避免的混淆 |
| --- | --- | --- | --- |
| 同轴参考纠正 | “A不用了，改用B的动作” | 当前动作换成B | 不把“弃用A”解释成回滚全部旧编辑 |
| 弃支参考复活 | “从V1继续，但用刚才弃掉分支里的动作示例” | 指定历史reference中的动作 | 旧分支人物、场景、发色均不自动带回 |
| 历史视频选择性复制 | “从V2继续，只采用V0里的动作” | 一个动作轴 | 不复制V0人物和场景 |
| 多参考角色分配 | “脸看A，动作仍按上轮B” | 分别沿不同轴继承 | 若一轮真的同时改脸和动作，必须拆成原子边；只重申已继承动作不算第二个编辑 |
| 参考冲突 | “用A的发型形状，但不要其发色” | shape | 当前main无hair shape，需扩图后再做，不能在现有数据上编造 |
| 参考排序干扰 | 图顺序变化，标签与角色不变 | 输出应不变 | 不要把位置编码变化误写成用户切换了reference角色 |

ImgEdit已明确研究内容记忆、内容理解与版本回退；MICE-Bench用非平凡约束和跨轮指代区别真正上下文需求。因此本项目应强调具体视频条件、reference角色和可追溯反事实，而不能泛称“首次多轮/首次回退”。[ImgEdit §3.1](https://arxiv.org/html/2505.20275v1)、[Edit-R2/MICE-Bench §3/E.2](https://arxiv.org/html/2606.05950v1)

## 6. 输入强度与评价的可操作对照

建议先用小样搭配，不把所有维度做成庞大笛卡尔积：

1. **reference来源**：独立asset-first；从目标提取再换背景/机位；近重复目标裁片（仅作为上界诊断）。三组来源明确，不能混成同一种实际用户示例。
2. **动作约束**：单canonical语义示范；same-view语义示范；明确time-aligned示范。GT阶段时间约束不同，评分随之变。
3. **文字强度**：直接写完目标细节；只说明编辑轴并指向reference。弱化只针对目标细节，不能删掉source-pointer或必要保留约束。
4. **历史必要性**：同reference不同source-pointer成对；去掉无关弃支应不变；去掉被引用弃支须承认信息不足。
5. **局部与全局分数**：先看人物保留、目标轴遵循与历史source，再看全图质量；背景plate覆盖大部分像素时，全图相似度不能独自代表交互成功。

reference-only与text-only作为诊断不自动是公平排名：缺失关键参考的模型无法知道某件未命名衣服的纹样，缺失关键历史的模型也无法知道V1的人物。它们用来确认信息是否必要，不用来惩罚没有获得同样信息的模型。

## 7. 目前最值得推进的下一项

已经把“继续做什么”落实到12对输入manifest，又继续对接root的正式相机和人体投影proxy，输出 [suite_observability.json](./suite_observability.json)。24条query中23条被排为优先人工复核，1条身份query的64px前向头部proxy弱，排到后面。它不是接受/拒绝gate：躯干朝向不是头部朝向，稀疏样本不证明遮挡，代表sex也不覆盖全部人物mesh，因此不把23条写成视觉通过。

进一步值得尝试的是**历史视频本身做reference**：它不用额外合成独立carrier视频，可以直接测“从V2继续，但只复制V0动作”。这会增加外观干扰，反而更适合检验选择性复制。当前已挖到1,164条这种重写候选；不能将它们全替代新目标第一次出现时必需的独立reference，也不能把反复引用造成的query数当作唯一参考媒体数。

另一条边界要提前清楚：如果要求“底图用V1、人物用V2、动作用V3”且两个属性都不同，它已经是多来源组合任务，不能为了保留“每边单属性”而偷称只有一条编辑边。可以拆成两条原子边，或新开组合任务轨道。reference角色继承也不等于跨分支自动合并：弃支里的reference仍可看见，只有新指令明确选用时才生效。具体条件契约见 [reference_task_contracts.json](./reference_task_contracts.json)。

复现先运行分析脚本，再运行构建suite脚本。图表使用已有ReportLab绘图库生成SVG；默认anaconda的matplotlib/NumPy ABI不兼容，未修改或安装环境。数值CSV/JSON为权威，图仅展示曲线。
