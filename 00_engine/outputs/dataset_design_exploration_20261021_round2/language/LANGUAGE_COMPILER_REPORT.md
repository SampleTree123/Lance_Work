# 历史指代的可判定编译实验

日期：2026-10-21。离线分析；未调用语言模型，未生成媒体，未改变数据图。当前主候选是第二轮 `motif_a7_f5_n3000_s20261021_{train,test}_uq1_ab3_*`，七个可变属性、固定横画幅。首轮五轴结果只作对照。输入文件及 SHA-256 见 `resolver_results.json`。

## 结论与输入契约

主候选的 5,000 条分叉中，40% 从初始版本继续、60% 从非初始版本继续。若初始文字完整说明七项属性，任一分叉都能用最多两项属性唯一指代来源；若初始文字只命名人物和场景，再加入几何可见性代理，测试集只有 561/1,000 条能用最多三项属性唯一指代。因此，语言可用性取决于实际提供的初始说明，不能从私有状态表直接填出一个看似清楚的指令。

这里不要求视觉优先。历史指令明确说过的事实，即使当前画面无法验证，仍可作为文本知识使用。几何代理不支持某个属性，也不等于已经证明画面看不到它；例如场景识别、具体发型和该衣物槽目前均未做像素验证。`hair=none` 时发色缺少可见头发载体，是另一种情况，不能与普通“代理未评估”混同。

编译器输出三种具有相同编辑结构的指令：

1. 显式轮次：从 V1 继续，只改镜头。
2. 属性描述：回到发色为粉色、人物为人物 P17 的版本，只改镜头。
3. 操作描述：从修改人物身份后的版本继续，只改镜头。

人物 P17、发型 H21 等是公开输入中的别名，必须配套人物说明或参考素材绑定，不能默认模型理解私有资产 ID。当前计划中的媒体路径为空，尚不是可直接训练的完整媒体样本。`garment_slot` 统一叫“该衣物槽”；其实际槽可能为女装全身或男装裤装，不能统称上衣。

## 解析规则

对每个历史版本、每项谓词采用真／假／未知：明确不符合才能排除；未知保留为可能答案。目标来源必须有充分知识确认符合。若只剩一个来源则接受；若多个来源经同一编辑得到完全相同目标状态，则保留全部等价答案；若仍对应不同输出则排除或请求澄清，绝不随机指定一个私有标签。

解析器对当前受限中文模板支持往返解析为结构计划，尚未声称能解析任意自然语言。事件描述通过历史操作索引生成；同类操作多次出现时需要补轮次或更细条件。本次主候选中的操作描述均可唯一解析，不代表未来任意长度历史都成立。

## 实际结果

下表为“恰好使用 1／2／3 个属性时，至少存在一个唯一来源描述”的分叉数量，同一分叉可以重复出现在不同列。

| 主候选输入知识 | train：1 / 2 / 3 项（共 4,000） | test：1 / 2 / 3 项（共 1,000） |
|---|---:|---:|
| 完整初始文字／全部状态上界 | 2,015 / 4,000 / 4,000 | 437 / 1,000 / 1,000 |
| 初始人物、场景文字 + 几何代理（样例默认） | 1,368 / 2,246 / 2,247 | 305 / 561 / 561 |
| 仅初始人物、场景文字 | 675 / 834 / 70 | 124 / 157 / 9 |
| 无初始说明、仅历史目标属性文字 | 0 / 0 / 0 | 0 / 0 / 0 |

“恰好三项”可能下降，因为没有三项已知事实可以合法补足；不应为了达到长度添加私有真值。`oracle` 仅为元数据上界；完整初始文字是可实际声明的输入方案，但会降低视觉识别负担。这两者数值相同不代表输入相同。

默认条件下共有 2,808 条分叉能生成最多三项属性的有效描述。100 条计划从这个可用子集中抽取，不能将样例的 100% 有效性当作全集成功率。测试集还出现文本已知、几何代理未支持的属性：身份 916、场景 1,000、动作 44、该衣物槽 76、发型 98、发色 8 次。这些是知识来源差异，除明示无头发等情形外，不是“视觉不可见”统计。

首轮五轴对照有 84.38% 分叉回到初始版本；这是旧数据的特征，不能用它描述当前主候选。其测试集元数据一项／两项／三项唯一指代为 874／1,000／1,000；默认输入为 789／888／889。更多细节保留在 `round1_resolver_results.json`。

## 去重与语义边界

`instruction_plans_100.json` 包含 100 个不同历史交互结构、300 个中文模板变体，对应 99 个不同媒体编辑边、95 个不同目标节点。三种说法共享同一结构标识，只增加语言覆盖，不增加 GT 视频或结构样本数；相同媒体编辑边置于不同历史时可以形成不同交互任务。抽样来源与图节点均记录在计划中。

选择旧版本与只恢复某个属性不同：前者先复制该版本完整状态，再做新编辑；后者从当前版本出发，仅把指定属性恢复，保留其他当前属性。`semantic_distinctions_examples.json` 给出实际历史下两者产生不同状态的例子，但不假定额外恢复状态已有渲染 GT。否定句“不要最后一版”通常仍有多个历史候选，不能当作精确回溯标签。纠正目标属性与纠正历史来源也使用不同的计划类型。

`rejected_attribute_examples.json` 保留 20 条真实歧义案例，包含未知造成的候选集、不同输出及拒绝原因。可把它们作为澄清任务的种子，但尚未生成用户澄清回答或额外 GT。

## 建议下一步

先固定初始输入文字契约，再扩展语言。最小可用方案是保留显式轮次作锚点，在可唯一解析的子集中配属性／操作变体；需要依赖文本才成立的描述明确记录 `knowledge_source`。小规模人工核对时重点检查别名是否真的展示、操作事件是否有重复、发型和该衣物槽是否在镜头中能被区分。当前输出已能作为输入计划，尚未验证自然语言理解性能。

## 复算与检查

运行 `compile_history_language.py --dataset round2_main` 生成主结果，`--dataset round1 --sample-per-split 0` 生成对照，随后运行 `audit_language_plans.py`。脚本仅使用标准库读取既有 JSON、JSONL。审计确认：100 个结构不重复；300 条模板能往返解析；全部接受候选产生预期目标状态。检查结果见 `plan_audit.json`，中文样例见 `CHINESE_TEMPLATE_EXAMPLES.md`。这验证受限计划的逻辑一致性，不验证像素可辨性或任意中文表述。
