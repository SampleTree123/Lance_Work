# 多轮分支数据：科学命题、反例与实际测试预算

2026-10-21，round2 独立研究。读取第一轮实际图/session 与第二轮图候选；所有新输出仅在本目录。没有训练模型，没有运行视频编辑器，没有渲染、修改 UE 或资产；以下“命中率”都是结构规则在 GT parent 标签上的结果，不是模型或视频性能。

## 1. 先决定要证明什么

建议主命题是：**系统在可见编辑历史中辨认用户指定的完整版本，对该版本执行当前编辑，并正确继承其他内容；历史改变时，结果应该相应改变，弃支的无关内容不应影响结果。**这比“有 2–5 条连续指令”更具体，也能被反例推翻。

必须拆开四种能力：①在一个已给定源上做单轮编辑；②每次接最新输出，抵抗递归质量漂移；③从历史多个候选中找到应继续编辑的版本；④拿到历史源后保留它的完整状态并继续。第③项和第④项都重要，但“第③项选中根很容易”不表示第④项不需要根视频，也不表示回退任务没有价值。

这不是自动成立的 world model 命题。Genie 的原论文研究动作可控、逐帧生成的交互环境；本项目边是设计者规定的属性干预，物理演化、接触和开放环境反应没有因此获得验证。更合适的表述是可控视频编辑的版本状态与历史依赖。[Genie，ICML 2024](https://proceedings.mlr.press/v235/bruce24a.html)。

也不要混淆三种“撤销”：整版回退后分叉，继承所选版本全部属性；只恢复旧衣服而保留当前动作/相机，是以 latest 为 source、从历史取一个属性值；取消某一步但保留后续编辑，则还涉及重放/变换后续操作。当前 whole-parent fork 只覆盖第一种。不能把这三种自然语言混写进同一 GT 规则。

相关工作已经有多轮视频记忆、长期图像编辑、视频参考与细粒度评测；“多轮”或“有 memory”本身不够形成清晰贡献。本轮较强的候选贡献是：**可审计的版本父指针 + 保留原子编辑的合成真值 + 证明历史必要性的成对测试 + 对 source 归因和 rollout 真值的明确区分**。均为待实验支持的研究路线，不作“首次”宣称。直接相关作品见 `RELATED_BENCHMARK_MATRIX.md`。

## 2. 深入一：怎样证明历史确实必要

### 2.1 成对历史，而非只做“去掉历史掉分”

构造两条历史：A 从远景变成近景，B 从俯拍变成相同近景；两边当前画面、此前指令“改成近景”、当前指令“从最初那版继续，只改成跑步”都相同。正确结果分别要保留远景与俯拍。

对只看 latest + 当前指令的系统，两项输入完全相同而目标不同；在均衡二选一组上，单项正确率最多 50%（不允许用隐藏 pair ID、文件名或评测顺序猜组别）。确定性系统不可能两边都对。完整历史的画面若能区分源，则有足够证据。这证明“历史中某个属性值必要”，比依靠模型实际掉分更直接。source pointer 在两边都可以是 root，因此仅统计 parent 命中不能验证是否真正继承了历史内容。

从第一轮实际 500 节点 test 图枚举得到 **1,360 组成对探针**：两段合法历史汇聚到同 latest，当前执行同一轴/同一新值，历史根的未编辑属性不同，两个合法目标已在节点库中。按预声明的轴/场景覆盖与复用规则选 100 组，仅用 **209 个已有节点**，不需要额外增加主视频端点。它们是两次编辑的独立分支探针，不冒充主候选“分叉后必有后续”的 3–5 次编辑 session。结果在 `history_necessity_probes.json`；该文件含审计 GT，不能原样作为模型输入。

| 100 组探针的历史差异轴 | 实际组数 |
| --- | ---: |
| action | 30 |
| camera | 21 |
| identity | 27 |
| site | 12 |
| hair_color | 10 |

209 节点实际覆盖 21 身份、18 动作、16 相机、5 site、7 发色；没有声称全部单值覆盖。灵感可比于 Winoground 的成对约束：只看平均单项分数容易掩盖只对一边的捷径，应补“两边都正确”的 group score；这里的图结构探针是本项目新构造，不是复用它的数据或任务。[Winoground，CVPR 2022](https://arxiv.org/abs/2204.03162)。

### 2.2 符号差异不等于模型可见差异

本轮已将 100 组 × 5 个 role 的 500 行按 motion/camera/aspect 与 root 导出的骨骼/轨迹代理连接，500 行全部匹配，但 **277 行角色性别不同于 planner 代表性别**。100 对中 58 对至少一边存在此不匹配；这不是代理无效，也不是角色可见性已经验证，只是不能把代表数据当所有人物的真值。

稀疏投影里 31 对的两个 root 都没有脚部入镜，5 对都没有下半身代理入镜；17 对至少一侧“头部达到 64px 且躯干朝前”的代理比例为零。action/camera 差异的 51 对中，没有两个 root 都缺下半身代理的情况，但 32 对至少一侧性别不匹配。**这些都只是排查线索**：没有脚不表示跑步/走路一定不可区分，轨迹哈希不同也不表示人能分辨，identity 在背面更不能仅凭配置 ID 认定可观察。

因此建议先审看 51 对 action/camera 探针；人物、发色、场景差异需分别补外观/背景像素证据。`paired_probe_observability.json` 保留每对风险，不把任何一对自动标 visual accepted。一个明确镜头的单帧也可能缺少动作差异证据；动作与运动相机参考需要视频条件，应与单帧条件分开。

### 2.3 歧义必须进入任务定义

若完整 public 输入相同而 hidden target 不同，说明缺证据，不能惩罚模型没猜中任意 canonical label。若“蓝衣那版”同时匹配近景和远景，且完整继承会产生两个不同目标，应允许询问/选择集合，或补清楚指代。若多个 occurrence 是同一完整状态，可报告严格指代与等价状态；如果多个不同状态在本轮编辑后相同，则还需下一节的 edit-conditional 等价集合。

LongMemEval 将知识更新、时间推理和无法回答时的 abstention 分开，且区分证据检索与回答，支持这里把选源、内容继承与证据不足分别评测；其文本记忆任务不能直接替代视频可见性验证。[LongMemEval，ICLR 2025](https://arxiv.org/abs/2410.10813)。

## 3. 深入二：比“选错源/输出错”更强的失败模式

**其他旧源可等价，但 latest 不等价。**历史依次红衣近景、蓝衣近景、蓝衣远景；从最初那版把衣服改绿。红衣近景和蓝衣近景都得到绿衣近景，latest 得到绿衣远景。仅通过 latest-counterfactual 检查，并不能用最终视频辨认选择了哪个旧 occurrence。

本轮独立计算了所有历史 source 在当前同一 edit 下的结果集合：第一轮 root-heavy main 有 40/1,000 个 fork 存在多个等价 source；第一轮 sourcebalanced 为 93/1,000；第二轮 stage1 balanced 为 100/1,000。**图 agent 随后生成的 strict motif a5/a7 已修正此归因问题：两者各 1,000 个 test fork 全部只有一个 edit-conditional 等价源。**旧结果保留作敏感性，不继续当成新候选的缺陷。来源与哈希在 `source_balance_comparison.json`。

**rollout 的两种正确性可能冲突。**第一轮应生成蓝衣，却实际生成绿衣；下一轮用户要求只改跑步、其余不变。保留实际绿衣是忠实当前可见源，但 nominal 图 GT 仍是蓝衣跑步。用一个 GT 视频评分会把继承旧错当成当轮新错，也可能奖励未经请求把绿衣偷偷修回蓝衣。必须同时报告：相对实际选中 generated source 的当轮变化/保持契约，以及相对 nominal 图路径的累计成功；首发错误、继承错误与新污染分别记录。不能用其中一个分数宣称同时满足两种定义。

**父指针正确，但输入绑定错位。**日志选 source 1，实际送入的是 source 2 的视频；或喂入 source 1，却仍把 latest 的相机/动作混进去。这类错误要核对实际媒体句柄、冻结 public 视图并做选源介入；一段正确的文字解释不能证明视频生成依赖了所选源。

**弃支污染和历史指令再执行。**保持当前 source 和当前指令不变，仅插入/改写已放弃分支的描述；目标应保持不变。若相机、衣服等随弃支变化，说明系统可能把全部过去要求累加，而非执行完整版本继承。和“必要历史改变必须改变目标”成对使用，才能区分恰当使用历史与无差别混入历史。

**隐含未来信息。**完整 session 的最终长度、未来指令、已渲染 target 的文件名或图邻接表若进入输入，在线任务会变成回看完整计划。当前 turn index 合法；planned total length 默认不公开。本目录把带总长度的规则明确命名为 oracle，只用当前 round 的规则另算，避免靠未来信息得出高分。

六个精确符号反例在 `semantic_counterexamples.json`，`validate_semantic_counterexamples.py` 已全部验证；它们是逻辑 fixture，不是假装已经渲染出的视觉反例。

## 4. 深入三：简单基线与分叉几何

### 4.1 已跑过的只是规则，不是学习模型

第一轮 test 共 11,200 次编辑，其中 1,000 次历史 fork。总选 latest 得到 **10,200/11,200 = 91.07%** 的所有回合源命中，但 branch-only 为 **0%**，全 session 源全对为 2,000/3,000。这个数主要由 2:1 session 配额和轮数决定，不能当作模型能力，也不建议靠压低它来改用户任务。

| 实际候选 test | 总选 root：fork 命中 | oracle 告知 forkflag，再用训练 round→parent 多数表 | fork 有多个 edit-conditional 等价源 |
| --- | ---: | ---: | ---: |
| 第一轮 main（root-heavy，历史对照） | 86.1% | 86.1% | 40/1,000 |
| 第一轮 sourcebalanced | 40.0% | 81.2% | 93/1,000 |
| 第二轮 stage1 balanced | 40.0% | 81.8% | 100/1,000 |
| 第二轮 strict motif a5 | 40.0% | 79.3% | 0/1,000 |
| 第二轮 strict motif a7 | 40.0% | 81.5% | 0/1,000 |

多数表只从对应 train 拟合、在 test 计数，不看视频和指令。**forkflag 在此由评测 GT 提供，是诊断 oracle**；实际系统能否仅凭指令判断是否分叉，尚未运行。带总长度的 oracle 表与仅 round 表在这几批恰好相同，不能据此认为未来长度可作为正常输入。没有 forkflag 的 round 多数表则等同 latest。脚本里的 state-oracle 还使用 GT edit axis/value 与 GT 历史，因此只能作符号 sanity check，绝不是生成视频分数。

### 4.2 高 round prior 有一部分由题目几何决定

第 t 次编辑若已知它是历史 fork，非最新历史槽位只有 0…t−2，共 m=t−1 个。要求 fork 后至少一次继续编辑时：L3 只能在 t2 分叉，且只有 root 一个旧源；L4 最晚 t3，仅两个旧源；L5 最晚 t4，仅三个旧源。

| 实际 test | m=1 / m=2 / m=3 的 fork 数 | 均匀随机挑历史槽位的期望命中 | round prior 在 m≥2 子集命中 |
| --- | --- | ---: | ---: |
| 第一轮 sourcebalanced | 284 / 534 / 182 | 61.17% | 73.74% |
| 第二轮 stage1 balanced | 284 / 541 / 175 | 61.28% | 74.58% |
| 第二轮 strict a5 | 274 / 531 / 195 | 60.45% | 71.49% |
| 第二轮 strict a7 | 287 / 546 / 167 | 61.57% | 74.05% |

均匀槽位是按实际 m 加权的机会基线，并非所有候选都语义合理的保证。m=1 的旧版本回退仍测试指令理解、历史媒体检索和内容继承，**只是没有多候选 source 选择难度**；应单列这一有用能力，而不是删除或称为无价值。

### 4.3 最小修改：保留长度，放开部分末轮分叉

用户允许末轮 fork；“全体必须 followup”是第一轮设计建议，不是用户硬规则。建议只改变分支位置配额：让 L3 的一部分或全部在 t3 末轮分叉；L4/L5 保留后续编辑，并增加 t3/t4 晚分叉。仍保持 L3/4/5 = 20%/40%/40%、root/nonroot = 40%/60%、2:1 linear/fork。

| 假想位置配额（1,000 fork） | 仍有后续编辑 | m=1 / m=2 / m=3 / m=4 | 均匀槽位机会命中 |
| --- | ---: | --- | ---: |
| 全 followup，各长度用最晚可选位置 | 1,000 | 200 / 400 / 400 / 0 | 53.33% |
| 仅一半 L3 末轮 fork | 900 | 100 / 500 / 400 / 0 | 48.33% |
| 全部 L3 末轮 fork；L4/L5 仍 followup | 800 | 0 / 600 / 400 / 0 | 43.33% |
| 全末轮（仅作边界对照，不推荐） | 0 | 0 / 200 / 400 / 400 | 33.33% |

以全部 L3 末轮为例，可使用 t3 的 L3 parent0/1=100/100，t3 的 L4=200/200，t4 的 L5 parent0/1/2=100/150/150：总 root400/nonroot600，且 800 条仍能检查继承后的下一次编辑。它没有改变用户规则，也没有为了数字而排除根回退；只是让“多候选推理”和“后续继承”分别有足够样本。

`analyze_branch_geometry.py` 还在这些声明的位置方案、5 个百分点质量网格上枚举了最小 round-prior，分别可达到 60%/55%/45%/40%；**不是完整图约束下的全局最优或保证**。实际合法边、source 可辨性、语义指令与视觉证据仍需重采样检查。不要仅为了降低 prior 追这些最小数；主报告应按 m、根/中间、lag、是否有 followup 分层，再补因果成对探针。

## 5. 500 test 视频到底提供多少覆盖

第一轮实际五个 site 的节点为 **96 / 85 / 223 / 63 / 33**，不是各 100；root 属于五个 site 的 session 数为 652 / 484 / 1,157 / 404 / 303。3,000 条中 **1,481 条跨 site**，仅按根场景归组并不能隔绝媒体依赖。

第一轮 500 节点全部被引用，437 个被用作 session root；实际用了 2,240 条有向边，11,200 次边引用。节点引用次数最少 7、最大 65，中位数 31。共享任意节点连起来的 session 依赖组件是 **1,542 与 1,458**；greedy 找到 89 条互不共享节点的 session，松上界为 floor(500/3)=166。**89 不是有效样本量，两个组件也不等于只有两个完全独立随机观测**，它们只是结构相关性的诊断；共享身份、场景和生成规则还会带来其他相关性。

源平衡并不自动解决依赖：第一轮 sourcebalanced 依赖组件为 1,556/1,444，node-disjoint greedy pack 为 93；第二轮 stage1 balanced 为 1,511/1,489，pack 为 90。后者 site 节点实际变为 100/100/102/101/97，确实改善场景值均衡，但独立性不是由这个均衡数自动获得。

### 5.1 两种改测试布局的路线

**优先候选：同一个 500 节点池承载主 session 与独立诊断视图。**保留场景留出，增加上述 100 对/209 节点的历史必要性探针、m 分层、弃支不干扰测试。这些共用媒体的结果单列，不假装增加 200 个独立世界。优点是不用把 500 再切成多个狭小图；短期研究问题更清楚。

**另一个候选：400 OOD + 100 已见场景对照。**本轮实际从旧图做贪心子集探测，非平均估算：

| 子集 | 节点 | 保留原 session | 诱导边 | 实际单值覆盖 |
| --- | ---: | ---: | ---: | --- |
| 原 test 选 400 OOD 节点 | 400 | 2,228 | 3,702 | 40 身份、25 动作、21 相机、5 site、7 发色 |
| 原 train 选 100 作 seen 对照节点 | 100 | 191 | 738 | 40 身份、25 动作、21 相机、16 site、7 发色 |

400 OOD 的五场景节点为 83/46/192/56/23。100 seen 虽然“单值全覆盖”，其中一个 site 占 **65 节点**，很多 site 只有一两个点，不能据此宣称对照充分；把它们移出 fit 将影响 **1,267 条原训练 session**。还需补 100 个新的训练侧端点、重采训练 session、再采对照才能恢复 2,500/12k。仅 2,228+191=2,419 条原 session 被这两个子集完整保留，不证明改布局后已有 3,000 条，更不证明按 6 session/node 就能凑出来。选中节点和真实覆盖在 `test_layout_probe.json`；原 run 未改。

## 6. 可实施的报告协议

主表先分：已给定源的编辑、m=1 的历史回退、m≥2 的 source 选择、fork 后继续编辑、整段 rollout。source 主要看 branch-only 且按 m/parentdepth 分层；当前媒体已给定的对照不能混入自动找源分数。

结果层同时报告编辑目标成功与未编辑属性保持；历史层同时报告必要历史干预敏感性与弃支不干扰；rollout 同时报实际所选源的局部契约和 nominal 图累计任务。视频画面再按时间稳定、身份、背景等维度拆分，并把视觉质量放在编辑确实正确的前提下解读。EdiVal 的官方项目区分指令执行、内容一致和质量；OmniEdit-Bench 进一步以 accuracy-aware penalty 防止未正确编辑却因原片视觉先验得高分，这些都比把所有指标平均成一个漂亮分数更符合本项目的问题。[EdiVal 官方实现](https://github.com/TianyuCodings/EdiVal)、[OmniEdit-Bench 原文](https://arxiv.org/html/2608.05049v2)。

测试统计首先报告固定 benchmark 的精确均值、每个 site 的结果和复用。不对 11,200 turn 做 iid bootstrap。只有 5 个被确定性选中的场景时，不把很窄的 turn 误差条当“所有未见场景”的总体置信区间。多 seed 重复生成可估计固定测试上的采样波动；这和新场景总体泛化的不确定性不同。

方法比较使用相同 prompt、相同历史可见性和相同 reference，先做逐对差值；预先冻结所有分层/可见性审查和阈值。paired probe 两边组成最小评测组，source/video 的 public 输入中不包含 graph 状态、答案指针、future target、隐藏 pair 标号或 planned length。若以后设计独立 family/多场景重复批次，按这些事先定义的 cluster 做不确定性分析；不能事后拆共享路径换一个 family ID 就制造独立样本。

## 7. 更值得继续发展的新路线

1. **最小充分证据阶梯。**同一任务依次给当前帧、当前视频、历史文字、历史关键帧、历史视频、明确选源。先用图和可见性检查判定哪个层级理论上足够，再用模型结果检验；不要把信息不足导致的失败当模型记忆弱。
2. **历史的因果相关性，而非仅历史长度。**一组成对历史改变必要属性，另一组只改变弃支干扰；前者目标要变、后者目标不变。两者共同检验系统有没有使用正确历史，且可以复用现有媒体。
3. **版本引用和属性引用分流。**“从旧版继续”与“只恢复旧衣服”都有实用价值，但继承规则不同。用同一历史、只改变这句话，构成最小语义对照；未来可以自然扩展到部分撤销/编辑重放，而不提前混入当前 whole-parent 契约。
4. **首发错误与恢复能力。**在冻结输出历史的诊断中，控制一个旧版本的小错误，比较用户“继续编辑、保持其余”与“同时修复旧错误”的指令。区分系统保留旧错、产生新错和获授权恢复；与长序列漂移另设轨道。MT-OPSD/LME-Bench 对十轮递归编辑分布错配的研究说明长期退化本身已有明确研究对象，本项目短分支应专注自己的可归因问题。[MT-OPSD / LME-Bench，2026-09-28 预印本](https://arxiv.org/abs/2609.35611)。
