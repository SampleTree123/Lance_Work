## 1. 任务定义

- **单轮**：`f(视频_in, 指令) → 视频_out`。
- **多轮**：`视频_0 --指令_1--> 视频_1 --指令_2--> 视频_2 --…`，在上一轮产物上继续编辑。
- **训练样本**最小单元 = `(视频_in, 指令文本, 视频_out)`；多轮样本 = 这种单元串成的链。
- **指令文本**当前不急于产出（可由"已知改了哪个因子"自动模板化 / 大模型改写生成）。

## 2. 编辑原子类型表（edit taxonomy）

> 对应总览第 3 节的"因子"。每类编辑 = 固定其它因子、只动这一类（= 配置图里的一种"边"）。

| 编号 | 编辑类型 | 例子指令 | 引擎里怎么实现 |
|------|----------|----------|----------------|
| E1 | 角色身份替换 | "换成另一个人" | 换 MetaHuman/角色，保持动作/相机/场景不变 |
| E2 | 服装更换 | "把她的外套换成红色风衣" | 换/改 outfit，保持体态姿势 |
| E3 | 肢体动作更换 | "让他从走路改成跑步" | 换骨骼 animation（retarget），保持身份/服装/场景/表情 |
| E4 | 场景替换 | "把背景换成森林" | 换 environment，保持角色/动作/相机 |
| E5 | 道具增删/更换 | "加一辆车 / 去掉树" | 增删 actor（道具/植被/车辆） |
| E6 | 配饰增删 | "给他戴上墨镜" | 在角色 socket 上挂/卸配饰 |
| E7 | 相机变化 | "镜头拉近 / 换成俯拍" | 改 camera 位姿/FOV/运动 |
| E8 | 光照/时间 | "改成日落 / 调暗" | 改 sun/sky/光照 |
| E9 | 天气/特效 | "下雨 / 加雾" | 改天气/后期/特效 |
| E10 | 全局风格 | "整体更冷色调" | 后期/分级（也可由非引擎来源补） |
| E11 | 面部表情 | "让她微笑 / 做出惊讶表情" | 改 blendshape 权重（ARKit/VRM），不换资产，**最易对齐** |

**✅ 已与作者确认（2026-06-19）**：
- **E1–E11 全部都要实现**，不分"必做/可选"，逐步推进、边做边解决。
- **（2026-06-19 拆分）** 原 E3「动作」拆为 **E3 肢体动作（骨骼动画）** 与 **E11 面部表情（blendshape）**——机制不同、且都是独立可对齐的编辑因子。
- **复合编辑（一轮改多个因子）也在范围内**，但以**单因子边为基本图元**；复合可作为后续"多因子边"补渲，或由训练侧合并相邻指令得到。
- 多轮链的长度/比例 → 属训练侧采样，数据侧不固定（见第 3 节）。

## 3. 数据怎么组织：配置图 + 沿游走渲染（关键决策 · 2026-06-19）

**背景**：作者判断"多轮链长度/比例是训练的事，数据侧只要有配套数据即可"。**基本同意，但成立有一个必须现在做对、后期补不回来的前提——端点复用。**

- 数据组织成一张**配置图**：
  - **节点** = 一个配置 C 渲出的视频。**确定性渲染**（固定随机种子/时间轴/相机、关闭时间抗锯齿抖动等随机性）→ 同一个 C 永远渲出**同一段视频**。
  - **边** = 一次原子编辑 C→C'（只改一个因子），自带"改了哪个因子 + 指令"。
- **关键前提：端点复用** —— 一条边的"输出视频"必须**就是**下一条边的"输入视频"（同一节点、同一文件），不是各渲各的。
  - ✅ 做对了：多轮链 = 图上一条路径 `C0→C1→…→Ck`，视频查节点库、指令来自每条边。**链长 / 各类编辑比例 / 是否复合 = 训练侧路径采样**，数据侧不固定 → 即作者说的"有配套数据，剩下是训练的问题"。
  - ❌ 做错了（配对各自独立随机渲、端点不一致）：链拼不起来，且**后期无法补救，只能重渲**。
- **高效构造法：沿"随机游走"渲染**。从一个基础配置出发，每步只改一个因子，走 k 步 → 得到 k+1 个节点视频 + k 条边。一次游走即同时产出：
  - 每条边 → 一个单轮配对；
  - 任意子路径 → 任意长度的多轮链。
  - 节点视频最大复用、渲染最省（渲"节点 + 边"，**不是**渲每一条完整链）。
- **训练侧仍需自理**：推理时模型吃自己上一轮输出会有漂移（如需 scheduled sampling）——属训练范畴，不影响数据构造。
- **因此数据侧真正的硬指标收敛为两条**：
  1. **各类编辑都要作为边出现、覆盖充分**（呼应"E1–E11 全都要实现"）；
  2. **端点复用 + 渲染确定性对齐**。

> 采样/游走的具体策略（基础配置怎么选、游走多长、每步改哪个因子的分布、如何保证图连通与覆盖）落到 [`sampling/`](./sampling/README.md) 细化；UE 侧实现落到 [`../../00_engine/`](../../00_engine/README.md)。

## 4. 多样性矩阵（diversity matrix · 初版来自作者）

| 因子 | 目标量级 | 备注 |
|------|----------|------|
| 角色 | ≥ 100 | 覆盖性别/年龄/体型/族裔等 |
| 服装 | ≥ 100 套 | 需能套到不同体型上 |
| 动作 | ≥ 20 | 需能跨不同骨架/体型复用（retarget） |
| 场景 | ≥ 50 | 室内/室外、风格多样 |
| 道具/植被/车辆 | 待定 | 可增删的 actor（驱动 E5） |
| 人物配饰 | 待定 | 帽子/眼镜/包等可挂卸小件（驱动 E6） |
| 相机 | 待定 | 一组机位/运动预设（驱动 E7） |
| 光照/时间 | 待定 | 一组光照/时段预设（驱动 E8） |

> 可编辑配对数 ≈ 各因子取值的**组合**，所以即便每因子只是这个量级，配置空间已极大；规模主要靠"采样多少配置/游走 + 每条游走多长"来调。
