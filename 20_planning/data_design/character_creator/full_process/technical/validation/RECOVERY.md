# 故障恢复手册

> 文档 ID：`TECH-VALIDATION-03`
> 文档类型：`technical`
> 生命周期：`current`
> 适用阶段：全部 Workflow
> 实现所有权：失败分类、恢复入口和禁止操作
> 验证所有权：无；本页提供所有 `VAL-*` 共用恢复语义
> 输出契约：`OUT-GLOBAL-VALIDATION-EVIDENCE`
> 最近核验：2026-08-25

## 1. 通用顺序

1. 停止提交同类新任务；
2. 保存当前 Request、Result、日志、弹窗和输入哈希；
3. 判断是否存在终态和副作用，避免同一作业重复执行；
4. 从最后一个已通过 Gate 恢复，而不是从任意中间文件继续；
5. 修复后使用同配置重试，或在配置变化时创建新版本；
6. 更新状态、计划需求和故障证据。

恢复后原验证结果不能直接恢复为 `passed`。输入未变时以新的 attempt 重跑同一 `VAL-*`；输入、实现或契约变化时先把旧结果标记为 `expired`，生成新版本输出并重新执行所有受影响验证。

## 2. CC/Bridge

未知弹窗交给用户；Undo 守卫只处理精确匹配。CC 关闭或内存失控时，不由自动化在线重启受限许可证环境；保留作业状态，用户重启后用新 heartbeat 继续。资产 Apply 失败时重新加载规范源项目，不在半装配场景继续叠加。

## 3. UE

崩溃后先核对自动恢复列表、脏包和 staging Actor。未知恢复包默认跳过，除非确认其内容是唯一未保存生产资产。导入失败按 Look/Action 单项恢复；不要覆盖错误 Skeleton 或批量保存未知脏包。

## 4. 图、文本和渲染

图/文本失败从 Builder 和冻结输入重建，不直接改 JSONL。渲染失败保持 Node 配置不变并增加 attempt；资产/路径/哈希错误永久失败，短暂进程/GPU 问题有限重试。同 Node 产生冲突媒体时整批停止审计。

## 5. 禁止操作

禁止删除未分类输出、覆盖权威 Bundle、移动 Vendor 资产、用历史文档覆盖当前配置、在未核对目标路径时递归删除，以及用降低质量掩盖视觉系统性错误。

## 6. 证据与状态回写

每次恢复记录原失败 `validation_id`、失败分类、输入哈希、最后安全 Gate、执行动作、新 attempt、结果和证据 URI。领域 Technical 负责操作步骤，Workflow Status 负责当前结果，当前计划只记录需求是否因此受阻；三者不能只在聊天中留下结论。
