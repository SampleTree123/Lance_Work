# 视觉审查

> 文档 ID：`TECH-VALIDATION-02`
> 文档类型：`technical`
> 生命周期：`current`
> 适用阶段：`WF-30/WF-40/WF-50/WF-60/WF-80/WF-90`
> 实现所有权：人工视觉 Gate、截图/视频证据和审查决定
> 验证所有权：`VAL-CC-01`、`VAL-CC-02`、`VAL-TRANSFER-01`、`VAL-UE-01`、`VAL-SCENE-01`、`VAL-RENDER-01`、`VAL-RELEASE-01` 的人工部分
> 输出契约：`OUT-GLOBAL-VALIDATION-EVIDENCE`
> 最近核验：2026-08-25

## 1. 原则

自动检查负责完整性、引用、哈希和数值；人眼负责自然度、穿模、构图、材质和动作可信度。二者不能互相替代。审查页面只展示权威产物或明确标记的候选，不允许缩略图与源文件错配。

## 2. 按阶段检查

- CC 身份：中性、闭眼、微笑、张嘴、左右 45 度；重点看眼球/眼睑、牙齿/嘴唇和头颈。
- Outfit：前后左右/三分之四，覆盖 slim/heavy/short；动作压力看腋下、腰胯、裆部、裙摆、鞋脚和头发/兜帽。
- UE Look：脸身肤色、材质白块、头发、胡须、眼睛、Morph 和 Skeleton。
- 动作/表情：首中末帧、T-pose、Root Motion、面部动态、眨眼和嘴唇。
- 相机/场景：主体居中、完整可见、无遮挡、四机位语义正确。
- 最终媒体：可解码、时长/帧率/分辨率正确、无黑帧、无突跳和系统性瑕疵。

## 3. 审查产物

推荐每个审查 Run 包含 `manifest.json`、索引 HTML、原图/视频、决定 JSON 和问题清单。网页可放大、逐视角/逐动作筛选，缩略图必须链接到真实源。决定至少使用 `accepted`、`accepted_with_known_risk`、`rejected`、`needs_rerun`。

Manifest 还必须写明 `validation_id`、对应 `OUT-*`、输入哈希、覆盖矩阵、审查人、审查时间和源媒体 URI。审查门户只是证据查看器，不是结果权威；结果必须回写对应 Workflow/Batch Status。

## 4. 例外处理

已知轻微服装穿模可以按批次明确接受，但必须记录受影响 Look/Action，不得把它提升为通用兼容。面部白块、T-pose、角色缺失、错误机位、严重眼球/牙齿穿模和错误身份属于硬失败。

## 5. 失效与恢复

输入资产、缩略图映射、源媒体、审查规则或覆盖矩阵变化后，旧人工决定标记为 `expired`。修复后重建审查 Run，不在旧决定 JSON 上直接覆盖；已接受风险变化时必须重新获得批次决定。
