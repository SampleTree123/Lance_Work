# 多图、参考视频与五轮编辑的序列预算分析

日期：2026-10-21。范围：当前代码只读核对、按实际bucket公式进行CPU算术估算；未解码全数据集、未做GPU峰值/速度测试、未修改训练实现。Technical owner：[训练接入](../training_integration.md)。关联[架构讨论](datamake_architecture_decisions_20261018.md)与[历史定位训练调研](datamake_source_routing_tool_call_research_20261018.md)。

## 1. 需求变化与实现边界

用户提出未来放宽每轮单参考图限制，允许多张图片甚至额外参考视频，编辑最多五次。本轮请求是分析资源影响，不是实施授权或确定最终媒体预算。现有optional_single_vit_v1仍只接受一张静态图；ADR-0018记录的是已实现第一版，多图/参考视频不因本报告而变为已支持。

已有混合训练profile的round_repeats包含第5轮，因此“五轮”本身不是全新的训练长度范围。新增压力是媒体数量、每段采样帧数/尺寸以及历史参考是否逐轮累积。五次编辑在直链结束后共六个视频；执行第5次编辑时仅V0至V4是五个可见历史，V5是目标，不能再作为干净ViT条件加入。

若“五次”限制的是全会话总编辑次数，则节点数有明确上限；若只限制每条根到叶路径深度，多条分支的总节点数仍可能超过六个，选择器需要独立的候选预算。这里不假定用户已决定哪一种。

## 2. 当前长度构成与硬限制

生成阶段近似长度：

```text
L_gen = 文本及边界
      + 选中路径上每个历史视频的ViT token
      + 所保留参考图片/参考视频的ViT token
      + 当前源视频VAE token
      + 当前目标视频VAE token
```

目前只有直接source与当前target有VAE；更早历史只有ViT。参考图只进ViT。未来参考视频若先沿用ViT角色，也不会自动增加一份参考VAE；如果另做参考VAE则必须单独计入。

理解选择阶段可以看全部已有候选分支，主要是文字与视觉ViT，没有源/目标VAE。两阶段是分别执行，不把两套序列长度相加当成一次forward长度。训练分开，推理顺序调用；条件KV与中间缓存是否释放会影响实际显存。

当前GT profile：VAE resolution480，ViT448，sample_fps12；源码数据变换按bucket而非固定方形。`model.max_tokens=65536`通过launcher传给总pack与单样本上限。GT的DataMake包装器在超预算时显式报错；不能假定自动压缩或安全截断。通用上游packer另有跳过超长样本逻辑，不能把它当作当前GT入口行为。

主干配置max_position_embeddings=128000并不等于当前训练允许128K，更不代表该长度下质量、RoPE位置、显存与编译行为已验收。现有最小padding只去掉无效尾部，不能缩减真实媒体token。

## 3. 公式与尺寸依据

对齐后的尺寸下：

```text
ViT视频：ceil(F/2) × (H/28) × (W/28)
ViT静态图：1 × (H/28) × (W/28)
VAE视频：((F-1)/4+1) × (H/16) × (W/16)，F为4k+1
```

静态图复制为两帧只占一个ViT时间位置。完整视频的时间位置随采样帧数线性增长。各自的H/W是预处理后的尺寸，不是原文件大小；把源图片换成4K文件但仍缩至同一bucket，不会自动增加主干token。

通过提取当前BucketResize.init_buckets函数并进行标准库CPU算术复核，16:9输入对应：VAE352×624；ViT bucket336×592再按28裁齐为336×588。故一个ViT时间位置为12×21=252 token，一个VAE时间位置为22×39=858 token。

| 媒体示例 | 主干token |
| --- | ---: |
| 单张16:9参考图，ViT | 252 |
| 448×448方形参考图，ViT | 256 |
| 8帧参考视频，ViT | 1008 |
| 16帧参考视频，ViT | 2016 |
| 61帧视频（ViT复制末帧到62） | 7812 |
| 61帧视频，VAE | 13728 |

61帧是设定的例子，接近既有CoinVE共同5秒窗的口径；不能把全部合成数据或任意采样器都假定为61帧。真实帧数需读取处理后的tensor。低帧率参考采样是建议，还没有独立媒体角色采样配置。

## 4. 第五轮的量级估算

以下统一假设五个历史视频都61帧且16:9，source/target也61帧。数字不含文字、工具定义、标记、保守pack预留与末尾padding；超过预算的判断因此已经足够，不超预算则仍需精确预检。

| 情况 | 视觉token合计 |
| --- | ---: |
| 第1轮，无额外参考：1份历史ViT＋source/target VAE | 35268 |
| 第5轮，无额外参考：5份历史ViT＋source/target VAE | 66516 |
| 第5轮，每轮3张图且15张都保留 | 70296 |
| 上项再加当前轮1个61帧参考视频 | 78108 |
| 每轮3张图＋每轮1个61帧参考视频，全部历史参考均保留 | 109356 |

这不是宣称旧训练第五轮已经超预算：旧样本帧数、比例与内容组合不同，本轮未全量扫描。作为敏感性对照，同样尺寸但每段49帧时，第5轮无参考为53808，加15张图为57588；每段73帧时，分别为79224和83004。可见轮数相同也不能推出成本相同。

每轮三张图在第五轮累计只加3780 token；同尺寸61帧参考视频每个加7812。若五轮均累积这种视频，单参考视频部分就增加39060。相比图片，未经控制的视频采样是更大的风险。

理解选择器在五个可见历史节点、15张参考图和当前1个61帧参考视频的同口径假设下，视觉为50652 token，没有27456个source/target VAE token。但这不是自动把所有参考都投入选择器的已定规则；应依据其语义作用及历史协议决定，且分支总节点数可能更多。

## 5. 长度与耗时/显存不能简单等价

主干投影/MLP等成本随token数增长；注意力成本取决于mask允许的query-key配对数量，广泛互相可见时有平方项。可用L平方作量级直觉，不能直接把其比例当作端到端训练时间或显存比例。当前块mask、条件缓存、编码器开销、重算与内核形状都会影响实测。

分块attention无需保存整张L×L矩阵，但仍需计算允许的注意力关系；它没有把真实视频token消除。[FlashAttention原论文](https://arxiv.org/abs/2205.14135)说明了通过分块减少HBM读写的机制。本分析不建议因此立即更换当前FlexAttention后端。

LoRA减少可训练权重及其状态，不消除长序列的基座前向和激活反传。当前0–25层重算、26–35层不重算的显存余量只能代表旧输入；长序列需重新测量。DDP八卡也不把一个样本的上下文平分到八卡。可以重新增加重算，但它不解决65K数据预算，也不降低真实序列注意力工作量。

生成推理有条件KV缓存，不能把训练prefill的平方估算机械乘上每个去噪步；目标query仍需读取更长条件KV，缓存本身也增长。不能从历史六十几GB的峰值推断新输入一定适合140GB显卡。

## 6. 建议：先管理媒体预算，再考虑结构改动

1. 保留当前source与target的VAE质量和时空对齐，避免先压缩直接编辑所需的细节。
2. 多张静态图先按当前ViT机制预算，显式绑定角色/对象/对应轮次；数量增加不是唯一问题，条件冲突也需验收。
3. 给旧历史视频和参考视频独立的采样策略。旧历史可先比较8/16帧；当前源视频保持较密ViT；动作参考可从16/32帧比较，必须覆盖完整相关动作，不能均匀抽帧后默认动作信息不损失。
4. 不自动给每张参考、每个旧视频增加VAE。需要参考VAE或学习式压缩时另立实验；固定数量token的resampler是后续模型改动，不作为本轮已决定内容。
5. 不静默删除旧参考。既有设计让参考留在所属历史轮次；仅保留当前参考会改变语义，须单独比较与决定。预算估算先按全部保留计算。
6. 建立每个样本各角色token清单、总数、长样本分位数和最大值；超预算应显式失败或按预定策略重采样，不能默认截断导致丢失prompt/参考/目标。

一个可讨论的组合：4个旧历史各16帧ViT，直接源视频61帧ViT，source/target VAE仍各61帧；每轮3张图全保留，当前参考视频16帧。视觉合计：

```text
4×2016 + 7812 + 2×13728 + 15×252 + 2016 = 49128
```

相对同媒体数量全部61帧的78108，少28980个视觉token，约37%。这是token减少，不是承诺耗时减少37%。如果每轮都保留一个16帧参考视频，则再加4×2016，变成57192，仍要加文字与标记。质量、峰值显存、速度均待测试。

## 7. 待确认与后续验证

待明确每轮参考图数量、参考视频最大时长/帧数、参考是否逐轮保留，以及“五次”是会话总数还是路径深度。先记录为未来需求，不把单图已实现合同直接改成多媒体已支持。

下一步如进入实施，先扩展角色明确的输入协议与分角色采样，再做CPU真实pack统计；随后对最长输入做单卡小规模前后向峰值、有限步推理与质量对照。参考图数据等待状态不因本次数量估算而改变，本轮没有启动测试或训练。
