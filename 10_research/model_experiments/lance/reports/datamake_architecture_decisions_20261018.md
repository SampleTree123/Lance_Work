## 2. 参考图：已经确定的规则

1. 每轮可以没有参考图，也可以有一张静态参考图；相机变化等任务可只用文字。
2. 第一版图片只经现有ViT编码，原有source/target VAE继续使用；图片不是新的源视频，也不是loss目标。
3. 图片提供文字指定的属性，例如衣服颜色、款式；不应自动把图片的人物、背景、姿态一起搬入视频。
4. 每轮最多一张，不做多视角或动作参考视频。单张图不充分描述完整动作，也不能确定衣服背面的细节。
5. 参考图VAE暂不实现。后续可复用冻结VAE，但需要额外条件角色、位置/mask/CFG处理，增加token与计算成本；更多细节不自动意味着更好地保留非目标内容。
6. 已实现的训练字段是与prompts对齐的 `reference_images`；推理是user turn的 `reference_image`。历史轮次的参考仍属于该轮，不自动成为后续指令的新参考。

完整问题回答、代码与2026-10-11工程验证见[参考图说明](datamake_optional_reference_image_20261011.md)。本次“暂不测试”不删除既有证据，也不把旧的小尺寸工程短测称为参考图能力的质量验收。

## 3. 历史起点选择：已确认的总体流程

```text
已有视频及各自编号、父子关系、编辑记录 + 当前用户prompt
                             ↓
                  理解任务：输出 source_video_id
                             ↓
              校验输出，必要时按推理策略回退
                             ↓
           解析为一个真实parent_id，固定本轮起点
                             ↓
       沿parent关系取原始视频到选中视频的唯一祖先路径
                             ↓
           选中视频作VAE source，执行当前编辑
                             ↓
           新视频分配递增编号，保存真实parent_id
```

这是一项两阶段推理设计，不要求两个独立大模型。模型负责理解选哪个版本，程序负责编号校验、找路径与准确设置输入。`source_video_id`是离散选择结果，不是神经网络权重参数。

### 3.1 默认继续，显式指向才改变起点

原始视频编号0，第一轮生成结果编号1，后续编号持续递增。分支不会重置编号，也不覆盖旧视频。

- 普通prompt，例如“把衣服改成蓝色”：输出 `-1`，使用本轮开始前最后一个已有视频。
- 显式起点prompt，例如“从视频0开始，把衣服改成蓝色”：输出 `0`。
- 显式语义指向，例如“回到换衣服之前的那个视频，再把背景改成雪地”：根据历史记录与内容选择对应编号。
- 单纯提到旧属性并不等于要求换起点，例如“把红衣服改蓝”不应仅因某旧版本有红衣服就跳回旧版本。

逻辑上可以分为“是否明确指定起点”和“指定的是谁”，但不要求新增两个分类网络；一个整数输出即可表达默认继续与指定版本。

本规则收窄了此前允许泛化语义猜测的建议：第一版优先学会正常指令不误跳历史，以及显式指令能准确选中。自然语言是否明确仍要靠上下文理解，不能只查是否含“从”字。

**待确认的标签边界：**显式说“从视频3开始”而3刚好也是最新版本时，建议保留具体编号3；普通继续才标-1。这个细节尚未最后定案。此前提出的“所有选最新都统一标-1”不应直接作为已确认规则。用户口语“第一个视频”和界面“视频1”的编号习惯也要在数据/UI中统一，避免原始视频0与第一轮结果1混淆。

### 3.2 编号和对应内容：像给视频贴标签

可以想象一本相册，每一页有页码、照片和一句说明。让人“选第3页”只需看页码；让人“找还没下雪的那张”需要看照片或说明。模型也需要这种对应关系。

| 标签 | 画面（实际由视觉编码提供） | 来历 |
| --- | --- | --- |
| 视频0 | 黑衣服、普通街道 | 原始视频 |
| 视频1 | 红衣服、普通街道 | 从0执行“衣服改红” |
| 视频2 | 红衣服、雪地 | 从1执行“背景改雪地” |

输入中将这些编号、编辑记录和对应视觉token组织在一起，而不是只给一个无标签的视频堆。表格里的画面文字只是解释，不意味着用文字替代真实视觉输入，也不假设模型能凭数字0/1/2自动知道视频内容。是否在最简单的显式编号任务先只使用元信息，是后续实现可选项；完整语义定位应能读取内容。

### 3.3 生成只使用选中节点的祖先路径

用户已明确：只使用从原始视频到本轮选中源视频这一条路上的内容。

```text
V0 → V1 → V2
 └─ V3 → V4
```

选择V4时，生成历史为 `[V0,V3,V4]`，不是按编号取 `[V0,V1,V2,V3,V4]`；选择V1则为 `[V0,V1]`。包含该路径的历史视频、产生它们的编辑指令，以及未来启用时属于这些轮次的参考图；排除其他分支。当前prompt和当前可选参考图另行加入。VAE直接source是选中的节点，其他历史视频沿用角色区分，不全部变为VAE source。

理解阶段可以查看候选历史版本以定位；生成阶段仅使用选中路径。两阶段上下文范围不同，是明确设计。第一版每个结果只有一个父节点，不包含跨分支合并或一次选多个source。

## 4. 为什么保存真实parent_id，不只保存-1

`-1`是“现在最后一个”的相对称呼，不是一个永远指向同一视频的身份。

例如本轮开始时最新是V3，模型输出-1，因此从V3生成V4。此时应保存：

```json
{"video_id": 4, "source_video_id": -1, "parent_id": 3}
```

以后再生成V5、V6，最新视频已经改变。如果只留下-1，重新加载会话或重建编辑树时，就必须重新推断它当时指谁；按现在的“最新”解释还可能指向自己或后来的结果。记录 `parent_id=3` 则始终明确V4来自V3。

应用场景包括恢复会话、画分支树、重建某结果的生成历史、准备训练监督及复现实验。输入参数用于表达用户本轮选择，parent_id用于保留实际发生的关系。应在生成前按本轮历史快照解析，保存后不随最新节点变化。

## 5. 理解和生成分别训练

**用户已确认：理解和生成是两个任务，分开训练，不通过在线选择结果把它们联合起来训练。**

当前已有双分支LoRA中的UND/GEN是视频编辑网络的参数分支，不代表已经训练过这里的“预测起点编号”任务。新增选择器需要独立的监督与验收，不能把旧理解分支名称直接等同于已具备可靠路由能力。

| 训练任务 | 输入与正确答案 | 训练要求 |
| --- | --- | --- |
| 理解/起点选择 | 历史及prompt → 正确source_video_id | 对正确输出做监督；预测错误不能替换成-1后当作正确，也不能因此跳过损失 |
| 视频编辑生成 | 正确parent对应祖先路径＋当前编辑 → 目标视频 | 用数据中真实起点构造训练输入，不依赖选择器当时预测对不对 |

建议理解任务采用常规正确答案token的交叉熵监督。训练并不需要先自由生成整数再判断如何计算loss；teacher forcing可以直接给正确答案计算损失。这是候选损失实现，选择器头部、输出格式与训练范围尚未实现。

**重要的参数边界：**分开训练任务并不自动消除共享参数干扰。如果先训练理解，再用生成loss更新同一组权重，仍可能遗忘选择能力。建议同一冻结基座配两个独立adapter，分别用于选择与生成；不需要常驻两份完整基座。两套adapter、冻结哪些层、是否另设轻量选择头尚待讨论，不能记为用户已经选定。

正常prompt与显式指定prompt都要验收。单报总体准确率不足，模型一直输出-1也可能在普通样本占多数时得高分；至少分别统计普通指令误跳率、显式指令选中率及非法输出率。数据具体制作不在本轮范围。

## 6. 推理失败回退：继续运行但保留错误事实

用户已确认：推理阶段不应因选择器回答格式错误等问题使整个编辑系统中断；这类错误按-1继续，使用最新视频。训练阶段则不能用回退掩盖错误答案。

建议分开记录模型原始输出、解析后的选择、最终parent和回退原因，例如本轮最新为V3，模型错误地输出不存在的99：

```json
{
  "raw_selector_output": "99",
  "parsed_source_video_id": 99,
  "effective_source_video_id": -1,
  "resolved_parent_id": 3,
  "fallback_used": true,
  "fallback_reason": "unknown_video_id"
}
```

上述字段名称是建议记录格式，不是已经实现的API。正常输出-1时 `fallback_used=false`，同样解析并记录真实parent。格式无法解析、空回答、不存在的编号等可检测的选择错误进入回退；失败统计不能因为最终生成成功就把选择判对。

还有一个检测边界：如果模型输出一个存在的编号1，但用户实际上想选0，仅凭输出格式无法知道它选错了。推理不能保证把所有语义错误都自动回退；需要单独评价选择准确性，并可在界面显示实际起点供用户发现。回退规则解决可检测的选择失败，不保证生成服务、媒体缺失等所有系统错误都能继续。

## 7. 决定、建议与下一步的分界

已确认：可选单图ViT；递增视频编号；普通prompt默认-1；显式起点定位；两阶段推理；生成只用祖先路径；保存真实父节点；理解与生成分开训练；推理非法输出回退、训练不掩盖错误。
