# 多参考 VAE、分支编辑与上下文预算：讨论方案

创建日期：2026-10-22；更新日期：2026-10-23。Technical owner：[训练接入](../training_integration.md)。状态：用户需求已记录；已确认仅当前轮参考、首选压缩历史ViT；具体序列布局、压缩参数和训练配方仍待讨论，尚未实现。当前代码仍是每轮可选单张 ViT 参考图；本轮没有修改模型、配置或启动训练。旧单图实现保留兼容，不把计划写成已支持能力。

## 1. 用户确定的输入语义

| 编辑内容 | 本轮参考 | 必须遵守的属性边界 |
| --- | --- | --- |
| 人物身份 | 目标人物1张正面面部照片 | 身体肤色、体形随身份改变；服装、发型等其他属性保持 |
| 发型 | 同一展示人物正面＋背面2张图 | 每种发型准备2名展示人物，每次随机选其中1人的两张；参考发色固定黑色；生成须保留源发色而非复制黑色 |
| 发色 | 无 | 文本指定颜色 |
| 服装单件 | 变化部件正面＋背面2张图 | 其余衣物、鞋保持 |
| 整套服装 | 各部件及鞋的正面＋背面图片 | 半身镜头仍提供完整穿搭；赤足用文本说明，无鞋图；总图数按部件数变化，尚无固定上限 |
| 动作 | 目标动作1段视频 | 使用目标镜头规则和对应横竖画幅，匹配动作相位、速度、时长 |
| 镜头 | 无 | 文本指定镜头 |
| 场景 | 当前镜头下目标场景1张空背景图 | 无人物；取对应视频初始取景；不要求场景参考视频 |

参考内容进入生成器时改用 VAE，不再沿用第一版参考 ViT。不同文件可有不同尺寸/宽高比，各自处理并记录网格；不能把多张图片当连续时间帧编码，否则会引入不存在的时序联系。动作参考是一个真实视频流，帧按时间编码。

数据由用户准备，本次不涉及生产数据。新合同另设版本，不原地改写 released 第一批或旧混合训练集。

## 2. 信息充分性：需要提前明确的限制

- VAE保留可重建的视觉细节，但VAE本身是有损表示，不会自动对齐参考与目标像素，也不会自行决定只迁移哪个属性。参考角色、条件注意力、训练监督共同决定效果。身份照片、衣服展示图属于非逐像素对齐参考；动作即使时间对齐，人物比例与画面位置也不一定逐像素对齐。
- 一张正脸不能唯一确定真实体形或全身肤色。若合成资产把固定身份绑定固定身体，模型可学该数据分布内的关联；这不证明对未见人物能从正脸准确恢复身体。保留用户输入规格，但验收要区分“身份相关身体变化”与“准确复现未提供的身体真值”。需要严格身体可控时再讨论文本体形/肤色说明等附加信息，不擅自增加全身参考。
- 发型参考黑发不是“同时改黑”的指令；两名展示人物能减轻身份绑定，但不能保证解除纠缠。需要检查换发型后源发色、脸、衣服保持。
- 单件/整套参考标明部件和front/back，鞋和赤足不能由素材数量猜。半身场景的完整穿搭参考仍参与输入，不自动丢掉当前未见部件。
- 单张场景初始图不能唯一决定移动镜头随后看到的遮挡区域/场景几何；静态与移动镜头分开验收。
- 动作对齐应使用共同时间轴与真实时间戳；需要明确“相位匹配”以目标动作时间轴为准，不能要求新旧不同动作的姿态逐帧相同。抽帧后仍覆盖完整时段，不能通过独立截断或变速破坏速度语义。

可借鉴现成方法的边界：作者[OminiControl代码](https://github.com/Yuanshi9815/OminiControl)区分主体参考与空间对齐控制，并给出可训练控制条件机制。这支持区分参考角色/位置的思路，不代表其FLUX实现或质量结论可直接搬到Lance。查阅日期2026-10-22。本方案以本地Lance官方VAE条件通路为实现起点。

## 3. 分开两次调用，也分开上下文预算

```text
会话持久化：所有节点视频、parent_id、指令、参考文件与元数据
                 │
                 ├→ 理解调用：候选节点ID/父子关系/编辑记录＋压缩历史ViT＋当前prompt
                 │                ↓ tool_call: select_source(source_video_id)
                 │          程序校验→解析为固定真实parent_id
                 │                ↓ 仅选该节点祖先路径
                 └→ 生成调用：路径文本/选定历史表示＋源VAE＋当前参考VAE＋目标噪声
                                  ↓ 视频解码
                           新ID＋真实parent_id写回会话
```

模型输出序列化工具调用，程序解析、校验、选源与裁剪路径。工具并非模型内部自动访问媒体。沿用默认-1、全局递增节点ID、生成仅用祖先路径、推理非法输出回退最新并留日志；合法但语义选错不能自动检测。一次请求在固定会话快照上解析-1。

理解器可以查看所有已存在分支的候选节点，不能看到将生成的target。生成器只看选中路径，永不按ID连续范围代替祖先查询。理解和生成是不同调用，序列长度分别计算，不相加成一次forward长度；切换adapter时不能跨权重复用KV。

参考VAE要求与历史ViT不冲突：前者为生成细节条件，后者为理解候选内容。建议第一版选择器用历史ViT＋指令及参考角色描述，不额外读取参考像素；参考文件仍随请求绑定、供生成阶段使用。如要支持“从与这张参考图最像的旧视频开始”这样的跨参考视觉定位，仅用历史和文字不足，必须另讨论理解参考像素的方案；不能悄悄恢复参考ViT或假定原UND天然理解新增VAE条件。

## 4. 生成序列与梯度建议

建议逻辑组成（准确块顺序、mask需实施验证）：

```text
选中路径的文字与可选历史ViT
当前编辑prompt、reference_id / 属性 / 部件 / 视角说明
选中source的ViT（第一轮实验保留）＋clean source VAE
当前各reference的clean VAE（各自独立T/H/W与媒体边界）
当前target VAE noisy tokens（训练）／纯噪声latent（推理）
```

1. 复用冻结的官方VAE、vae2llm、时间与位置编码机制，首先不增加新编码器。图像T=1；视频采用VAE合法帧数。角色文字先用已有词表，不默认新增未训练特殊token。若新增角色embedding或投影，必须明确训练与checkpoint保存范围。
2. source与reference都是无噪声条件；只有当前target按官方flow-matching加噪、监督velocity。参考与source不进入target MSE。复用当前代码的clean timestep约定，注意打包的负无穷值经过sigmoid后才是实际t=0，不能把预sigmoid数值0误当clean。
3. target可读source、当前参考、被保留的路径信息及同一target内部token。条件块不得读target真值/噪声以形成监督泄漏；跨样本/非祖先分支隔离。训练与缓存推理mask必须一致。
4. 参考采用各自网格，不能因为宽高碰巧相同就将衣服图当目标视频对应像素；不同媒体边界/角色与空间位置编码要共同审查。动作的物理时间不能简单视作拼接后的连续视频时间。
5. VAE编码使用冻结权重/no_grad；并不把Transformer里的参考条件hidden states全detach。生成loss仍需通过条件注意力训练LoRA学会使用参考。沿用“生成的历史视频detach”约束与本点并不矛盾。
6. 参考VAE不替换source。当前CFG按ViT/文本分类的开关不能冒充参考VAE强度控制；第一版固定参考始终可见，再独立设计reference dropout/CFG如有需要，不能一次删掉所有VAE或删去target噪声。
7. 缓存键包含文件hash、变换、采样时间、VAE/adapter版本与上下文策略。缓存可减少编码或重复prefill，不会消除参与注意力的真实token。上下文或参数改变时不可复用旧KV。

## 5. 历史压缩：持久化完整不等于每次全量输入

2026-10-23用户已确认：参考内容只作用于所属编辑轮次，生成时只输入当前轮reference VAE，不重复输入历史轮次的参考图片或视频。原因是同一属性可能先后被编辑为不同目标，旧参考持续作为条件会增加冲突风险，并使上下文随轮数累积。训练和推理应使用相同规则；当前轮无参考时不自动补入旧参考。历史参考文件及关联保留用于追溯/重放，不删除素材，也不把历史参考的缓存KV带入后续生成。此规则更新目标架构，当前旧单图实现尚未修改。

已发生的编辑通过选中的source视频继承；仅当前参考这一决定不删除历史视频或历史文字；历史ViT的首选方案由下方后续决定明确。代价是源视频未呈现、只有旧参考包含的细节，在后续视角变化时不再有直接参考保证。

2026-10-23后续确认：生成阶段保留选中祖先路径上更早历史视频的压缩ViT，作为当前首选H1。用户认为保留视觉历史更有益，这属于方案选择，不代表效果已实验验证。具体抽帧、空间尺寸、压缩比例尚未确定；不由此冻结理解选择器的历史预算。直接source通路不属于本次早期历史压缩/删除消融的变量。

以下三个历史策略登记为未来消融，用户明确目前不执行；每个实验的训练与评估使用一致历史策略：

| 方案 | 更早祖先的视觉 | 直接source | 用途与风险 |
| --- | --- | --- | --- |
| H0 | 原完整ViT | ViT＋VAE | 质量基线；长样本可能超限，仅在共同可行子集比较 |
| H1（用户确认首选；未实现） | 压缩ViT；8/16帧及降空间分辨率仅为候选，参数未定 | ViT＋VAE不变 | 保留版本外观证据；可能漏掉短暂动作/背面细节 |
| H2 | 不输入早期祖先ViT，只留路径文本 | ViT＋VAE不变 | 成本低；复杂历史指代与源中不可见细节可能退化 |

H2不是让理解器也失去视觉；两阶段配置独立。去掉直接source ViT是另一个消融，不与删旧历史同时更改。本版不实现旧参考的自动检索/重新注入。若未来需要复用，应另行约定如何显式绑定为当前轮参考，不能由本决定推导为已支持。

不先增加学习式压缩器、不先提高max_tokens、不把旧历史全部换为VAE。先控制实际输入；需要更长上下文再单独核验位置范围、质量、mask、编译和显存。

### 5.1 未来消融登记：历史视频与历史 prompt

2026-10-23用户要求同时登记历史prompt对生成是否有正面作用的消融。以下均为`planned_not_started`，本轮不实施、不训练、不推理，也不把历史prompt有益或有害写成已知结论。

| 实验 | 分组 | 固定条件 | 主要问题 |
| --- | --- | --- | --- |
| 历史ViT | H0完整保留 / H1压缩保留（首选） / H2删除早期历史视觉 | 当前prompt、当前参考VAE、源/目标、路径文字政策、训练数据与预算 | 压缩能否保留历史信息收益；删除后质量/成本如何变化 |
| 历史prompt | P1保留祖先路径历史编辑prompt / P0移除这些旧prompt | 当前prompt、当前参考及其角色说明、选定源、相同历史ViT策略（先用H1）、节点标签/结构与损失 | 历史编辑文字提供上下文还是带来过期目标干扰 |

历史prompt实验只针对生成阶段较早轮次的编辑指令，不删当前用户编辑prompt，不删当前参考角色说明；编号/媒体边界结构在两组一致。对照的精确定界及模板在实施前冻结。当前设计仍沿用路径文字作为基线，这不等于本轮已确认必须永久保留所有历史prompt。

理解选择器可能依赖历史指令定位版本，不能在生成prompt消融中同时改选择器。优先用真值parent或固定相同的路由结果，保持输入源一致；先单因素比较，不把ViT删除与prompt删除捆成唯一对照。若后续需研究二者交互，再独立登记组合实验。

保持同一数据划分、初始化和训练更新/目标样本预算，记录各组实际token/计算量，训练与推理使用对应政策；仅在旧模型推理时删条件只能称敏感性检查。H0超长时在共同可行样本上公平比较，并记录被排除样本，不能静默换短数据后比较整体平均。

评价包括编辑遵循、非编辑属性保持、历史指代、同属性多次覆盖是否回退到旧目标、时序一致性、每角色token、峰值显存、耗时；质量与成本分别报告，尚不设置未经讨论的验收阈值。

## 6. 可复核的长度估算

当前GT profile明确max_tokens=65536；这是本地现行pack限制，不是本轮核实出的官方模型统一上下文上限。上游通用packer默认与模型位置配置不同，不能互相替代。下表不是GPU实测。

按当前VAE等效压缩4×16×16（含patchify）：

```text
L_vae = (floor((F-1)/4)+1) × (H/16) × (W/16)
L_vit = ceil(F/2) × (H/28) × (W/28)
L_gen = L_text + L_kept_history_vit + L_source_vae + L_current_refs_vae + L_target_vae
```

H/W取各自处理后合法尺寸。图片F=1，可与source尺寸不同；参考分辨率需新增独立配置，当前单图接口没有这套VAE政策。

示例采用当前16:9桶：source/target VAE为61帧352×624，每份13728；ViT为62帧336×588，每份7812。16帧历史ViT为2016。方形参考图若实际编码512×512，每张1024个VAE token；448×448为784；256×256为256。这里512是建议实验尺寸，不是当前480桶自动产出的大小。

第5次编辑前有5个历史节点，其中4个早期祖先和1个直接source。假设所有媒体按上述尺寸处理，且只保留当前参考：

| 历史策略 | 整套穿搭示例：8张512²图 | 动作示例：1段61帧352×624视频 |
| --- | ---: | ---: |
| H0：5份完整历史ViT | 74708 | 80244 |
| H1：4份16帧历史＋完整source ViT | 51524 | 57060 |
| H2：只留source ViT | 43460 | 48996 |

均未含文字/边界/padding；8张只是4部件各2视图的例子，不是用户规定的上限。服装和动作是两类编辑，表中没有默认同轮同时输入两套参考。最长路径长度不约束整棵分支树候选总数，两阶段需要独立预算。

动作参考优先比较保持全部61帧、空间降至256×448（7168 token）与完整352×624（13728）；空间不足再比较同一完整时间窗33帧（7722）/17帧（4290），并记录真实时间间隔。降分辨率会影响手指/接触细节；抽帧会影响快速运动与相位。当前位置路径中存在固定second_per_grid_ts=1.0，不能声称只改采样器就已经正确表达不同帧率，需要单独审查。

建议精确pack预检输出每个角色token、总长、最大值和分位数；预留文本与标记空间，例如先用56K视觉软预算、65K总预算作候选，不作为已定配置。超限不能静默删prompt、reference或target。序列减少比例不直接等于耗时减少比例，partial checkpoint/DDP也不能解决输入合同超限。

用户提出生成source/history ViT共用低规格、理解候选保留标准ViT、参考图/视频分别设VAE规格，见[形状与预算示例](datamake_stage_specific_media_specs_20261023.md)。这扩展了此前只调整早期历史的讨论范围；生成source的规格也成为候选变量。参数尚未冻结，既有消融仍暂缓。

## 7. 训练任务和实施顺序建议

- 理解任务：历史候选＋当前prompt，监督序列化单工具调用，答案token做CE；默认继续和显式回溯分别采样/评价。生成任务：真值parent→祖先上下文＋source＋当前参考，target官方flow loss。先用GT source/history隔离参考能力，不把在线错误选择带入训练。
- 建议同一冻结基座分别使用selector/generator adapter，推理切换；两任务分开训练不会自动避免共享LoRA被后一个任务覆盖。参数隔离方式待确定。
- 分支共享节点不得分散到train/validation；至少按整棵树/共同原始视频分组，复用媒体另审计。参考资产可分seen/unseen评估；只见过相同身份/服装资产时不能宣称泛化。

实施阶段：

1. 冻结数据协议：节点ID/parent、真实媒体路径/hash、prompt、reference列表（kind/attribute/part/view/group_id/timebase）、目标尺寸/时间窗；训练标签与推理输入分开，selector看不到真值parent答案。
2. 先建CPU pack预算与角色审计；实现多图/单视频VAE条件，保持文本-only回归；不同时大改路由和历史压缩。
3. 小样本参考生成验证：发型/服装双视图、单脸、完整穿搭、场景、动作、无参考。正确参考/换参考/空参考对照，检查目标属性响应及非目标保持；有限样本过拟合只验证可学通路，不当泛化质量。
4. 在同样数据、训练预算和随机种子下比较H0/H1/H2；训练与推理用相同压缩策略，不能仅推理删历史就下结论。报告编辑质量、属性保持、历史指代、时序、token、峰值显存和吞吐。
5. 用真值parent先验证分支路径生成，再训练独立选择器，最后集成tool_call推理。报告默认误跳、显式选中、格式非法、回退率及端到端质量。
6. 新长度范围重新做单卡最坏形状、分布式梯度/连续恢复验证，再准备正式训练。保留PEFT/DDP、最小padding、VAE缓存等已有优化；部分重算层数按新峰值复验。旧checkpoint不得直接当严格续训状态。

每阶段独立验收；本轮仅记录计划，不执行上述实验。

## 8. 下一轮优先讨论
