# Lance contextual video_edit smoke 测试记录

> 日期：2026-07-03。
> 目的：验证 Lance 能否在一次 `video_edit` 上下文中同时接收原视频、历史指令、历史输出和当前指令，并生成下一轮视频。

## 结论

- contextual turn1 和 turn2 均已在 H200 上生成成功。
- turn2 使用的 v0 结构是 `C0 video -> e1 history text -> C1 video -> e2 current text -> target`，不是连续单轮回灌。
- Lance 数据层确认 turn2 会形成 2 个 VIT 条件块、2 个 VAE 条件块和 1 个 target VAE block。
- 代码复查后发现 v0 config 以 text 结尾，会让 Lance `video_edit` system prompt 使用错误的 `vision_type=text`。`contextual_video_edit.py` 已修正为 v1：JSON 采用 `text -> video -> history videos...`，让 Lance 模板旋转后得到“视频在前、文本在后”，同时保持 system prompt 为 `input video`。因此本报告里的 v0 输出只作为执行链路 smoke，不作为质量判断样本。
- v1 turn1/turn2 已重新生成并抽帧检查。结论是：执行链路通过，但视觉质量失败，不适合作为可用多轮编辑能力结论。
- 2026-07-05 复查 BAGEL 与 Lance 打包逻辑后，确认 v1 的主要结构问题：它把 C0 和 C1 都作为 clean VAE `ref_source`，但只有一个 noisy VAE target，导致 Lance edit 的 source-target 位置对齐条件失效。`contextual_video_edit.py` 已升级到 v2 role-aware config；历史视频标为 `history_vit`，只进 VIT，最新视频标为 `direct_source`，作为唯一 clean VAE source。
- v2 role-aware turn2/turn3 已在 `94766` allocation 上生成成功。turn2 明显优于 v1 all-source：没有重绘成全新非雪林场景，并能在 turn1 结果上加入暖金色夕阳。turn3 暴露新问题：局部“蓝色狗项圈”容易错误绑定到人物外套；单轮对照基本保住红外套，说明多历史上下文会增加局部属性绑定干扰。
- 2026-07-08 新增 full-conversation multi-turn chat A 方案原型：参考 `Jayce-Ping/Lance@8b002b5` 的 conversation engine，但保留 DataMake 的 v2 视觉策略，即历史视觉只进 VIT，最新视觉作为唯一 clean VAE direct source。该方案保留历史 user/assistant turns，不把历史 prompt 拼进最新 prompt 字符串；当前已通过静态语法检查和 conversation JSON 生成测试，尚未跑 GPU 视觉结果。

## v1 视觉检查

抽帧接触图：

```text
outputs/video_edit/contextual_smoke_v1_01/review/contact_sheet_v1_turn1_turn2.jpg
```

观察结论：

- `turn1` 指令是“把男人外套改成亮红色，同时保持女人、狗和行走动作不变”。输出确实出现了红色上衣/外套，但主体严重漂移：同行女性基本消失，黑狗变成白狗，人物身份、服装形态和构图都明显改变。
- `turn2` 指令是“在雪林场景中加入暖金色夕阳光，同时保留雪和主体”。输出几乎变成全新的高饱和夕阳道路/森林场景，雪地、人物和狗都没有稳定保留，属于编辑失败。
- 因此 v1 contextual 路径只证明 Lance 可以运行这种上下文格式，不证明模型具备可靠真多轮视频编辑能力。

## v2 视觉检查

抽帧接触图：

```text
outputs/video_edit/contextual_role_v2_01/preview_frames/v1_v2_comparison.jpg
outputs/video_edit/contextual_role_v2_01/preview_frames/turn1_turn2_turn3_contact_sheet.jpg
outputs/video_edit/contextual_role_v2_01/preview_frames/turn3_prompt_comparison.jpg
outputs/video_edit/contextual_role_v2_01/preview_frames/single_vs_context_collar_comparison.jpg
outputs/video_edit/contextual_role_v2_01/preview_frames/prompt_style_comparison_with_keep_red.jpg
outputs/video_edit/contextual_role_v2_current_only_full_01/preview_frames/current_only_full_contact_sheet.jpg
```

观察结论：

- v2 turn2 相比 v1 all-source 有明显改善。v1 turn2 变成非真实夕阳道路/森林并丢失主体；v2 turn2 保持了 turn1 的红衣人物、狗、雪林和行走构图，并成功加入暖金色夕阳光。
- v2 turn2 仍继承 turn1 的严重错误：原始双人场景变成单人，黑狗变白，原始身份和构图已经不可恢复。这是 turn1 单轮质量问题，不是 turn2 结构单独造成。
- v2 turn3 原 prompt 要求“给黑狗加亮蓝色项圈并保持人物不变”，输出把人物外套改成蓝色，没有稳定编辑狗项圈。原因之一是 prompt 与当前 direct source 不一致：turn2 中狗已经不是黑狗。
- 使用更明确的 structured/local prompt 后，contextual turn3 仍把人物外套改成灰色或明显漂移，局部项圈绑定仍失败。
- 直接用 turn2 输出做普通单轮项圈编辑时，红外套基本保持，局部结果优于 contextual turn3。这个对照说明：v2 解决了 v1 的 VAE source-target 结构错误，但多历史 VIT 上下文仍可能干扰小目标局部属性绑定。
- prompt style 对照显示，复述历史编辑不是必须，且在这个样例里有副作用。`structured` 和 `timeline` 都把红外套改灰，也没有稳定生成蓝项圈；`current-only` 只写“给狗加蓝项圈”时，蓝色更明显落在狗脖子附近，但红外套变棕/灰；`current-only` 加必要保持约束时，红外套和夕阳保持最好，但蓝项圈不明显。
- 当前推荐：多轮视频上下文继续保留，但文本默认只写当前轮指令；如需保持已接受属性，只在当前 prompt 里写少量明确约束，不复述完整历史编辑链。
- `contextual_role_v2_current_only_full_01` 从 turn1 重新开始完整跑了 current-only 三轮。结果明显更合理：turn1 保住双人主体并把男士外套改红；turn2 在同一主体/雪林构图上加入暖金夕阳；turn3 保住红外套和夕阳，并把蓝色加到前景狗脖子/胸背附近，但仍不是精确的小项圈。这个结果支持 v2 role-aware + current-only 作为当前 Lance 多轮验证的默认格式。

## 下一步

1. 保留 v2 role-aware 作为当前正确结构；不要回到 v1 all-source。
2. 测试 full-conversation A 方案：历史文本作为独立 turns 保留，和 `contextual_role_v2_current_only_full_01` 做同视频/同 prompt 对照。
3. 默认 prompt style 仍以当前轮自然指令为主；A 方案的关键变量是是否保留历史 turn，而不是把历史 prompt 拼入当前 prompt。
4. 后续测试应换更短、更清晰、主体更稳定的视频，优先测大尺度编辑和中尺度属性编辑，暂时不要把“小项圈”作为 Lance 多轮能力的主判据。
5. 若继续研究 Lance 多轮，需要比较 `history_vit` 数量、历史文本 turn、少量保持约束和 direct-source-only 结构对局部属性绑定的影响。
